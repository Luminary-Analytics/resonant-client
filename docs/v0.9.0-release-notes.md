# Resonant Client v0.9.0

This release turns long-running Ollama coding sessions into visible,
steerable, lifecycle-managed work and establishes the capability-driven,
multimodal-ready foundation for future open models.

## Highlights

- Adds a persistent, polished live-run surface with phase, elapsed time,
  progress, todos, and active sub-task visibility.
- Keeps the composer available during execution so users can steer a running
  agent or queue follow-up turns.
- Serializes queued turns on the server while keeping the WebSocket responsive
  to stop, permission, and user-input messages.
- Adds acknowledged `cancel.requested` → `cancel.completed` lifecycle events
  and an explicit Stopping state in the UI.
- Terminates complete Windows subprocess trees with Job Objects, including
  model-generated `start /B` and `start "title" /B` server commands.
- Removes empty cancellation artifacts and prevents interrupted turns from
  appearing as duplicate failures.
- Adds capability profiles for context, modalities, tool calling, reasoning,
  structured output, continuation, and safe concurrency, enriched from Ollama
  runtime metadata.
- Adds normalized text, image, audio, video, document, file, and diagnostic
  content parts. Text-only models now receive an explicit fallback instead of
  silently losing attached media.
- Locks outcome quality, completion reliability, verification, maintainability,
  and wall-clock performance ahead of token efficiency in the canonical
  agentic-harness north-star contract.

## Model and context policy

- GLM 5.2 Cloud retains its 999,424-token default context window.
- DeepSeek V4 Pro and Flash retain their 1,048,576-token default windows.
- Normal model generations remain uncapped by Resonant.
- Context is organized for maximum usefulness; token and compute usage remain
  secondary diagnostics rather than primary optimization targets.

## Validation

- Live steering test against a real HTTP server confirmed queued handoff,
  process-tree termination, and released ports.
- Live stop-button test confirmed Stopping state, backend acknowledgment,
  complete cleanup, and return to an idle composer.
- Exact Battleship command regression:
  `cd ... && start /B node server.js 2>&1`.
- Full automated suite passed before release.
