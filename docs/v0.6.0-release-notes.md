# v0.6.0 — agent self-improvement loop

**Date:** 2026-05-06
**Predecessor:** [`docs/v0.5.18-release-notes.md`](./v0.5.18-release-notes.md)
**Theme:** lift the [Hermes Agent](https://github.com/NousResearch/hermes-agent)-inspired three-layer self-improvement architecture (prompt nudges + agent-callable tools + background curator) onto resonant-client's autonomous mission daemon. This is the FIRST minor that changes the central agentic flow rather than instrumenting it. v0.5.x was instrumentation + coverage + ground-truth; v0.6.0 is the compounding investment.

## a1: skill provenance + bundled reference skills

`orchestration/skills.py` already had a complete skill library (Skill dataclass with id/name/description/scope/triggers/tokens/etc., save/load/list/match, auto-deprecation, Voyager-style plan-graph extraction). What was missing: the **provenance gate** that makes the curator safe.

Two new fields on the `Skill` dataclass:
- **`created_by: str = "agent"`** — `"bundled"` / `"agent"` / `"user"`. The curator only touches `"agent"`. Default `"agent"` is back-compat for pre-v0.6 saves (which all came from the auto-extractor).
- **`pinned: bool = False`** — user-marked durability. Pinned skills are exempt from `is_deprecated` regardless of fail rate or unused days, and exempt from curator archival regardless of provenance.

Plus `Skill.is_curator_touchable()` — the predicate the curator uses (created_by="agent" AND not pinned).

New module-level helpers:
- `archive_skill(skill, reason="")` — curator-driven archival. Distinct from `deprecate_skill` (different destination dir `_archive/` vs `_deprecated/`). Refuses non-touchable skills. Writes `_archive_reason.txt` for forensics.
- `list_skills_filtered(...)` — adds `created_by` + `pinned` filter args.
- `set_pinned(skill_id, pinned)` — round-trip pin/unpin.

New package: `resonant_client/orchestration/bundled_skills/`. Two pinned reference skills shipped:
- `rigorous-grill-spec-refinement` — the 5-beat question pattern codified from the linux-bridge field run (acknowledge → bridge → options → recommend → invite override).
- `autonomous-mission-iter-discipline` — per-iter conventions codified from v0.5.6→v0.5.9 field findings.

Plus `install_bundled_skills(force=False)` — idempotent installer using `importlib.resources` for pip/wheel/pyinstaller compat. Tiny YAML-frontmatter parser (no PyYAML dep).

`pyproject.toml` updated with `[tool.setuptools.package-data]` to ship the `.md` files in installed wheels.

42 tests in `tests/test_skills_provenance.py`.

## a2: mission-iter skill extractor

Sibling to the existing `skill_extraction.py` (which distills skills from PLAN-GRAPH completion). The new `skill_mission_extraction.py` distills from autonomous-mission **iter** completion — a different abstraction (roadmap items + REFLECT verdicts) that became the daemon's primary unit of work in v0.5.x.

- **`IterContext` dataclass**: minimal slice of iter state (roadmap item title/description, iter count, intent_id, project_path, REFLECT verdict + summary, criterion pass tally, decision-request flag, verdict_overridden flag).
- **`should_extract_from_iter(ctx)`**: conservative threshold — verdict==satisfied + not overridden + (bash_passed + vision_passed) ≥ 2. Trivial iters skip without a model call.
- **`SKILL_EXTRACTOR_SYSTEM_PROMPT`**: focused system prompt instructing the model to either emit `(no skill)` (the right answer most of the time) or a SKILL.md body in the agentskills.io format. Explicit guidance: *"BETTER to write zero skills than to pollute the library."*
- **`extract_skill_from_iter(ctx, *, backend, max_tokens=4096)`**: end-to-end. Threshold check → `backend.stream()` (matches the Session.run protocol so the v0.5.17 streaming-stub harness just works) → response parse → skill save. Best-effort: any exception is logged and swallowed.

33 tests in `tests/test_skill_mission_extraction.py`. The streaming-stub harness from v0.5.17a1 drives the extractor deterministically without a real backend.

## a3: deterministic curator

**Design pivot from PLAN-SELF-IMPROVEMENT.md spec:** original called for a model-driven curator that consolidates narrow skills into umbrellas. Pivoted to a deterministic curator for the alpha — pure Python, no model call, just stale-archival via the existing `is_deprecated()` heuristic. Model-driven umbrella consolidation deferred to v0.6.1.

Why split: the deterministic stale-archival on its own keeps the library from rotting and is loadbearing. Adding model-driven consolidation at the same time bundles two risks. Ship the cheap guardrail first.

- **`CuratorAction` / `CuratorReport`** dataclasses for tracking what was done.
- **`should_run_curation(project_path, min_hours=24)`**: rate limiter with paused-flag respect.
- **`run_curation(project_path, ..., dry_run=False)`**: lists curator-touchable skills (with `include_deprecated=True` — the curator's whole point is to find deprecated skills), checks `is_deprecated`, archives matches via `archive_skill`, writes `run.json` + `REPORT.md` to `~/.resonant/projects/<hash>/curator/<ts>/`, updates state file.

**Provenance enforcement is three layers deep**: `list_skills_filtered(created_by="agent", pinned=False)` only surfaces touchable candidates, `archive_skill` internally calls `is_curator_touchable()`, and `is_deprecated()` is exempt for pinned skills. Defense in depth.

27 tests in `tests/test_skill_curator.py`.

## a4: skill loader + prompt formatter

The injection layer that makes the prior alphas actually useful at runtime. Wraps the existing `find_matching_skills` and adds policy + presentation.

- **`match_skills_for_query(query, project_path, max_skills=8, min_score=0.05)`**: pinned-always-included rule. Both project + global pinned skills surface regardless of token overlap. Then token-overlap matches via `find_matching_skills` (with `partial_threshold=min_score` threaded through to override the original's 0.6 default — that was for "auto-substitute" semantics; we need a much looser gate for "is this worth surfacing in the planner's prompt").
- **`format_skills_for_prompt(loaded)`**: numbered markdown block with 📌 markers for pinned, match scores for non-pinned, `skill_view <id>` view handles per skill.

NOT wired into the autonomous mission daemon at a4 — that's the GA. a4 ships the matching + presentation in isolation.

25 tests in `tests/test_skill_loader.py`.

## v0.6.0 GA: daemon integration + docs

The wire-up that turns the data layers into a closed loop:

**`DaemonHooks` extended with two optional callables**:
- **`extract_skill_hook`**: called from `_run_full_reflect` AFTER the autonomous_reflection event when `verdict=="satisfied" and not verdict_overridden`. Production wraps `skill_mission_extraction.extract_skill_from_iter`. Tests pass `None` to skip. Best-effort: hook exceptions are caught + logged; the daemon continues.
- **`queue_curation_hook`**: called from `_emit_stop` ONLY when `is_complete and reason == "satisfied"`. Production wraps `skill_curator.run_curation` (in a background thread to avoid blocking the daemon's terminal-event sequence).

**Docs:**
- [`docs/skills.md`](skills.md) — usage guide covering format, lifecycle, scopes, provenance, the line between skills and memory.
- This release notes file.
- ROADMAP.md timeline + capability track #17 added.

**10 new tests** in `tests/test_skills_daemon_integration.py` covering both hooks: fires-on-satisfied, doesn't-fire-on-continue, doesn't-fire-when-overridden, no-hook-no-call, exception-swallowed (for both hooks).

## What this delivers (versus v0.5.18)

The big behavioral change: **mission iters now compound knowledge across runs in the same project.**

Before v0.6.0:
- Linux-bridge mission's path-mismatch finding got captured in the field-observation doc and shipped as v0.5.8a2.
- Generic patterns (Tauri quirks, Pydantic conventions) lived in chat history and evaporated at the next session.

After v0.6.0:
- Successful iters auto-extract reusable patterns into `<project>/.resonant/skills/<id>/` with `created_by="agent"` provenance.
- Future planner runs in the same project see a curated list of those skills in their context.
- The curator archives stale skills (>90d unused) without ever deleting — defense in depth.
- The user can pin skills they trust + author their own (`created_by="user"`) without the curator touching them.

It's not magic — the system-prompt nudges + the threshold heuristic decide WHAT to extract; the model emits `(no skill)` more often than not (which is correct behavior). The compounding effect is gradual but durable.

## Carry-over to v0.6.1+

- **Model-driven curator** (umbrella consolidation): forked agent merges narrow sibling skills into broader umbrellas. Spec exists in PLAN-SELF-IMPROVEMENT.md; deferred to v0.6.1.
- **CLI commands**: `resonant skill list / view / pin / archive / promote`. Stubbed; full surface in v0.6.1.
- **Production wire-up of the hooks**: the GA adds the hook *plumbing* in DaemonHooks. The actual factory that wires `extract_skill_from_iter` + `run_curation` into a real-mission daemon happens at the call site (likely `gui/autonomous_factory.py`) — small follow-up.
- **Embedding-based matching**: keyword/Jaccard works at the v0.6.0 scale (dozens of skills). Embeddings unlock cross-language / synonym matching at the cost of an embedding-model dep.
- **User-global skill elevation** via `resonant skill promote --global`.
- **Field-run validation**: dispatch mdcheck or similar with v0.6.0 enabled, verify skills compound across two missions in the same project. P0 carry-over from v0.5.x.

## Strategic context

This is the FIRST minor where the goal isn't "make the existing flow more visible / more tested / more stable." It's "make the existing flow get better over time." That's a different kind of investment — compounding rather than linear.

The runway from here is open: smarter matchers, model-driven consolidation, cross-project skill borrowing, possibly external skill marketplaces. None of those are in v0.6.0, but the substrate is in place.
