# Resonant Client v0.11.12

## Manage projects from the sidebar

- Right-click a project in the sidebar for **Open**, **Rename**, and **Remove
  from sidebar**. Previously the only right-click menu on the rail belonged to
  the Add-project button.
- **Rename** sets a display name for the sidebar. The folder itself is not
  touched, and the name now survives reopening the project — which it did not
  before, because opening a project rebuilt its sidebar entry from the folder
  name. Renaming a project back to its folder's own name returns it to
  following the folder, so a folder renamed on disk is picked up again.
- **Remove from sidebar** stops tracking the project. **The folder and its
  sessions are left completely alone** — reopening the folder brings everything
  back. The confirmation says so, and the behaviour is covered by a test so it
  cannot quietly become a real delete.
- The built-in Playground project cannot be removed; its menu entry is shown
  disabled rather than hidden, so its absence is explained.

## Internal

- Continued the frontend restructuring: the settings and overlay surfaces, and
  the run-card and live-run rendering, each moved into their own file. The main
  frontend file is down from 12,459 lines to about 9,900.
- The event dispatcher's simple cases became a lookup table. An event wired to
  a handler that does not exist now reports the problem instead of being
  silently ignored.

## Validation

- Full Python suite: 2,929 passed, 2 platform-skipped. Ruff clean.
- Verified against a running server: the context menu opens on a real project
  tile with the correct actions, stays inside the window, disables Remove for
  Playground, and a rename was round-tripped end to end against a real project
  and reverted.
