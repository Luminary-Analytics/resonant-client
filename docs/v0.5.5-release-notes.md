## a1: smoke baselines + variance diff

A variance report tells you the absolute convergence rate + timing of N runs. What you actually want before tagging a release is the DELTA: "after this change, did wordcount-pro converge faster, slower, or about the same?" That's the question baselines answer.

**Workflow:**
```
resonant-smoke variance --spec wordcount --model pro --n 3
resonant-smoke baseline set --spec wordcount --model pro \
  --from smoke-runs/variance-wordcount-pro-n3-<ts>.json
# ...make a change...
resonant-smoke variance --spec wordcount --model pro --n 3 --diff-baseline
# → markdown report includes "Diff vs baseline"; exits non-zero on regressions
```

**Implementation:**
- `resonant_client/smoke/baseline.py` — per-project storage at `<project>/.resonant/smoke-baselines/<spec>-<model>.json`. Per-project so different repos can have different acceptable convergence profiles.
- `BaselineDiff` dataclass captures deltas + regression / improvement narratives.
- `diff_against_baseline(current, baseline)` — pure function, refuses cross-(spec, model) comparisons. Convergence drops are ALWAYS flagged (no relative threshold). Timing regressions need both ≥20% relative AND ≥10s absolute to qualify.
- `_render_baseline_diff_section` extends the variance markdown report with a "Diff vs baseline" block: headline, 3-row metric table, regression / improvement bullets.
- New CLI subcommand tree: `baseline set / list / show / rm`. Plus `variance --diff-baseline` for in-line diffing.

**32 new tests** covering disk I/O, threshold math, diff computation, markdown integration, CLI parsing.

## a2: sidebar mission browser

The orphan banner (v0.5.3a2) only surfaces broken missions. The roadmap inspector (v0.5.3a3) only shows the CURRENT session's mission. Neither helps you discover or navigate among multiple autonomous missions in a project. v0.5.5a2 adds a dedicated browser.

**Backend:**
- `list_autonomous_missions(state)` returns ALL autonomous missions (running + complete + paused + failed), sorted newest-first by `autonomous_started_at`. Each entry carries `is_live` and `is_orphan` flags so the frontend can display orphan markers without re-running detection.
- New WS command `autonomous_missions_list` for explicit refresh.
- `init` payload includes `autonomous_missions` so the browser populates immediately on connect.

**Frontend:**
- New sidebar slot above the agent list: each mission shown as a clickable row with phase icon (∞ live / ✓ complete / ⏸ paused / ✗ failed), feature title, age, optional "orphan" pill.
- Click handler reuses the existing `switch_session` WS command — same code path as clicking a regular session.
- Refresh wired into `_syncMissionUI` (current-highlight follows session) and the autonomous lifecycle events (started / ended / failed).

**11 new backend tests** covering empty cases, all four phases included, sort order, `is_live` / `is_orphan` flag derivation, defensive handling of malformed records.

## a3: `resonant-smoke ci` subcommand

A curated suite shaped for cron / GitHub Actions. Runs default specs `minimal,wordcount` (roguelite excluded — too slow for CI; opt in via `--specs`). Exits 0 only when every (non-skipped) spec converged AND no baseline regressions surfaced.

```
resonant-smoke ci --model pro
resonant-smoke ci --model pro --specs minimal,wordcount,roguelite
resonant-smoke ci --model pro --diff-baseline
resonant-smoke ci --model pro --n 3                  # ship-readiness gate
```

**Implementation:**
- `resonant_client/smoke/ci.py` — `DEFAULT_CI_SPECS`, `parse_specs_arg`, `CISpecResult`, `CISuiteResult`, `run_ci_suite`, `render_ci_markdown`.
- Defaults: n=1 per spec (fast smoke); user bumps to 3 for ship-readiness gating.
- Markdown report: per-spec status table + per-spec baseline-diff narratives when regressions / improvements surface.

**30 new tests** covering parse_specs_arg edge cases, CISpecResult / CISuiteResult semantics (especially the regression-fails-suite case), render_ci_markdown layout, and CLI parser plumbing.

## a4: inspector timing + copy-roadmap-path

The v0.5.4a4 inspector showed terminal-mission criteria state but not duration. v0.5.5a4 closes the loop.

**Backend:**
- Inspector payload gains `last_iteration_iso` (most recent log entry timestamp) and `elapsed_seconds` (started → last-iteration delta). Best-effort ISO parsing — unparseable timestamps or negative deltas (clock skew, hand-edits) return None so the GUI renders "-" instead of bogus data.

**Frontend:**
- "Ran for 3m 12s" timing line for terminal-phase missions only (live missions hide it; the chat-header badge already shows live elapsed).
- "Copy roadmap.md path" button in inspector footer. Uses navigator.clipboard with an execCommand fallback for non-secure contexts (file://, some pywebview environments). Click feedback: label flips to "Copied!" with a green tint for 1.5s.

**5 new backend tests** for the timing field derivation.
