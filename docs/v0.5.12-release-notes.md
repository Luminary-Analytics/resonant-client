## a1: drop Geist Mono CDN dep (ORB-blocked)

The v0.5.11 post-build E2E pass — the first run under the new standing rule — surfaced exactly one failed network request:

```
GET cdn.jsdelivr.net/npm/geist@1.3.1/.../geist-mono/style.min.css
→ ERR_BLOCKED_BY_ORB
```

Chrome's [Opaque Response Blocking](https://chromestatus.com/feature/4933785622675456) refuses to deliver this stylesheet response, so the `@font-face` never registers and the chain falls through to Cascadia Code anyway. The user impact was already cosmetic (system mono renders code blocks fine), but the broken request was real noise in `preview_network --filter failed` and a defense-in-depth concern: every load failing on a third-party CDN.

Fix:
- [resonant_client/gui/templates/index.html](../resonant_client/gui/templates/index.html): removed the `<link>` to the Geist Mono CSS.
- [resonant_client/gui/static/styles.css](../resonant_client/gui/static/styles.css): removed `'Geist'` from the font-sans chain (Geist Sans was never actually loaded — the CDN only ever pulled geist-mono css), removed `'Geist Mono'` from the font-mono chain.

Visual delta on Windows: code blocks render in Cascadia Code (the canonical Windows mono font, ships with Win10+) instead of Geist Mono. Cascadia is a near-identical-feel substitute. macOS users get SF Mono. Linux falls through to JetBrains Mono / Fira Code / Consolas / monospace.

No new tests — this is an HTML/CSS asset change. Verified via `preview_network --filter failed` showing zero entries (was 1 in v0.5.11).

## a2: engine/server.py triage — legacy marker + minimal coverage

The v0.5.11 audit found `engine/server.py` at 0% coverage. Investigation turned up a clear architectural finding: the paired client side (`resonant connect <ws_url>`) was REMOVED in v0.4.4 when v0.4.0 cut the multi-backend infrastructure (see [tui.py:1260-1264](../resonant_client/tui.py)). The server side was left in place anyway.

Result: the engine WebSocket server is still importable + runnable from `resonant serve`, but no bundled client knows how to connect to it. External tools implementing the JSON-over-WebSocket protocol could still drive it, but none ship.

The post-refocus product is GUI-first via `resonant-gui` (a different WebSocket server in `gui/server.py`). `engine/server.py` is a legacy asymmetry — the question of whether to remove it entirely is a strategic call (flagged in [ROADMAP.md](../ROADMAP.md) → "Open work" carry-over).

This alpha is a **triage**, not a full coverage push:

1. Top-of-file docstring updated with a "⚠ Legacy status" block explaining the asymmetry, the audience the module no longer serves, and pointer to the strategic decision.

2. New [tests/test_engine_server.py](../tests/test_engine_server.py) with 11 tests across 2 classes:
   - `TestEngineServerConstruction` (7): default + custom host/port, max_steps/max_tokens threaded through to Session, auto_approve=True in server mode, _clients starts empty, _run_task starts None, backend reference held for the streaming-on-connect path.
   - `TestEngineServerImports` (4): class importable, module deps resolve, expected methods exist (handle_client / start / _run_session — the surface the TUI calls), legacy marker present in docstring (locks in the triage note so a future refactor that strips it consciously decides to drop the marker).

NOT covered (intentionally):
- `handle_client` async routing — needs a websocket mock harness that doesn't pay off for legacy code.
- `_run_session` worker thread — same reason.
- `start()` — boots a real server forever; not a unit-test target.

Coverage delta on `resonant_client/engine/server.py`: **0% → 24%**. Enough to catch import-level regressions; not enough to claim "this code is exercised."

## a3: harness/state.py lifecycle coverage (61% → 99%)

[tests/test_harness_state.py](../tests/test_harness_state.py) covered path resolution + the legacy `.resonant-harness/` migration. The actual sprint-lifecycle methods on `HarnessWorkspace` — `set_active_sprint`, `record_evaluator_verdict`, `set_contract_status`, the `update_*` helpers, run_history JSONL append/read, teacher-escalation logging — were untested. The harness is opt-in (default off post v0.4.0 refocus per cluster 5), but anyone who DOES opt in needs the lifecycle to work correctly.

Silent regressions in these state-write methods would have shown up as "my sprint contract isn't picking up the verdict" or "the run history is missing events" for an opted-in user — invisible to default-config testing.

New [tests/test_harness_state_lifecycle.py](../tests/test_harness_state_lifecycle.py) with 36 tests across 8 classes:

- `TestSpecRoundTrip` (4) — read/write, unknown-keys-dropped (forward-compat), update_spec partial, update_spec ignores unknown keys.
- `TestEvaluatorReportRoundTrip` (1) — round-trip with all fields populated.
- `TestUpdateMethods` (3) — `update_progress` / `update_sprint_contract` / `update_evaluator_report` all read-mutate-write correctly.
- `TestHandoff` (3) — read-when-missing returns empty, write+read round-trip, write strips trailing whitespace and appends a single newline.
- `TestRunHistory` (6) — empty-when-no-file, append+read, limit returns most-recent N, skips invalid JSON lines, skips blank lines, records include timestamp.
- `TestTeacherEscalations` (4) — same shape as RunHistory.
- `TestSetActiveSprint` (3) — full lifecycle (writes contract, resets progress, wipes evaluator state, records run event), generator role sets implementation phase, clears acceptance_evidence.
- `TestRecordEvaluatorVerdict` (6) — pass/revise/blocked verdicts each update contract status + progress phase correctly, defensive guard when verdict is for a different sprint than the active contract, unknown verdict leaves phase unchanged, run event recorded.
- `TestSetContractStatus` (6) — proposed→planner, approved→generator, implemented→evaluator status-to-role default mapping, explicit role overrides default, unknown status leaves phase unchanged, run event recorded.

Coverage delta on `resonant_client/harness/state.py`: **61% → 99%** (only 4 lines uncovered; all defensive branches that need fault injection — empty-file branches, OSError on shutil.copy2, JSONDecodeError in teacher_escalations — and they're already covered by analogous patterns elsewhere).
