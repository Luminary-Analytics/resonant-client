# v0.5.4 — simplify the planner story, prove the retry path, polish the harness

**Date:** 2026-05-03
**Predecessor:** [`docs/v0.5.3-release-notes.md`](./v0.5.3-release-notes.md)
**Theme:** trim the v0.5.3 backlog. Pick simpler defaults where the smart routing wasn't earning its complexity. Bake the "validate the rare paths" practice into the harness instead of leaving them as TODO items.

## TL;DR

Four alphas, all carryover items from the v0.5.3 deferred list:

- **a1: remove `PLANNER_BY_TIER`.** Always use PLAN_DEEP. The per-tier routing dict was a footgun for new models — they defaulted to PLAN silently. PLAN_DEEP is a strict superset of PLAN, so this is a pure cleanup.
- **a2: `FlakyPlannerBackend` + `--inject-planner-failure` flag.** Walker auto-retry (v0.5.1a3) had never fired in any smoke. Now there's a deliberately-flaky test scenario that forces it to fire end-to-end.
- **a3: markdown reports.** `resonant-smoke run` and `variance` now emit `.md` summaries alongside the JSON record — paste-ready for PRs and release notes.
- **a4: inspector for terminal missions.** The sidebar inspector used to vanish the moment a mission stopped; now it stays visible for `autonomous_complete` / `autonomous_paused` / `autonomous_failed` with a colored phase badge so users can review what actually shipped.

Full pytest **1538 pass / 2 skip**. Net **+35 new tests** across the four alphas.

## a1: remove `PLANNER_BY_TIER` routing

Why now: v0.5.3's deferred-items list called this out. The routing was added in v0.5.1a2 because `pro` failed PLAN's strict "emit JSON immediately" contract. PLAN_DEEP fixed it. After v0.5.2 made pro the default, the routing dict became a liability:

- New models (kimi-k2.6, glm-5.1, minimax-m2.7) defaulted to PLAN unless someone remembered to add a routing entry. Silent failure mode.
- PLAN_DEEP's prompt is literally PLAN's prompt with a Phase 1 exploration block in front. Flash works fine under it.
- Adding a new model now means: register it in `network_defaults` + `smoke/runner.MODELS`. No planner-routing edit. Two-file change instead of three.

What changed:
- Deleted `PLANNER_BY_TIER` dict + `planner_for_model()` from `gui/autonomous_session.py`. Replaced with `_DEFAULT_PLANNER_SPEC = NodeSpecialization.PLAN_DEEP`.
- `IntentService.start_intent`'s `planner_specialization=` override is preserved — non-autonomous callers (anyone outside the autonomous-mission daemon) can still pin PLAN explicitly.
- 4 routing tests dropped, 3 pin-the-new-default tests added.

## a2: walker-retry validation via `FlakyPlannerBackend`

The walker auto-retry path was added defensively in v0.5.1a3 to handle malformed planner output. In 5+ smoke runs across v0.5.0–v0.5.3, the path had **never fired** — every planner emitted parseable subgoals on the first try. Good news for the prompt; bad news for confidence in the retry path itself.

This adds a deliberately-flaky test scenario.

**`resonant_client/smoke/flaky.py`** — `FlakyPlannerBackend` wraps any backend, sniffs system prompts for the PLANNER / DEEP PLANNER signature, and intercepts the first N planner calls to return a malformed (no-JSON-envelope) response. Subsequent calls forward unchanged so the retry has a real chance to recover.

**CLI flag:** `resonant-smoke run --spec minimal --model pro --inject-planner-failure`. A converged mission with the flag set proves the retry path works end-to-end. A non-converged one points at a real bug.

10 unit tests bracket the wrapper's behavior:
- Pass-through for non-planner calls
- Intercept on the first planner call
- Forward on the second
- PLAN_DEEP recognized
- Zero-failures no-op, negative-N rejection
- Multi-failure intercepts
- Attribute delegation via `__getattr__`
- A defensive test that the planner-prompt signatures we sniff for actually appear in the real `system_block` text — so a specialist-prompt rewording fails loud rather than silently disabling the intercept.

The existing `test_walker_planner_retry.py` already covered the walker bookkeeping side. Together they bracket the path: walker handles `subgoals=[]` → spawns retry; FlakyBackend reproducibly produces `subgoals=[]`; the CLI flag wires them in a real smoke.

## a3: markdown reports

JSON artifacts are great for tooling but unfriendly for skimming a PR description or pasting into release notes.

**`resonant_client/smoke/report.py`** — pure functions:
- `render_run_markdown(SmokeResult)` — single-card summary with status badge (✅ / ⚠ / ✗), key-value table, iter-duration list, optional Error row.
- `render_variance_markdown(VarianceReport)` — headline (`K of N converged, P%`), Timing rollup (median/min/max/stddev), Stop-reasons histogram, per-run detail table.

**CLI:** both `run` and `variance` now accept `--report path.md`. When the flag is omitted, the markdown is written alongside the JSON with a `.md` suffix. Always emitted — emitting markdown is essentially free.

24 unit tests cover the renderers + CLI flag plumbing.

## a4: inspector for terminal-phase missions

The v0.5.3a3 sidebar inspector hid itself the moment a mission stopped. That was the wrong default — most of the value of seeing which criteria are green is for the user reviewing what the mission actually accomplished, not just monitoring a live one.

Pure frontend change:
- New `_AUTONOMOUS_PHASES` Set: `running` + the three terminal phases (`complete`, `paused`, `failed`).
- `_currentAutonomousIntentId()` now returns the intent_id for any of those phases.
- Phase badges (green / yellow / red colored pills) appear in the inspector header for terminal phases. Live missions get no badge — visibility itself is signal enough.
- "Next item" block is hidden for terminal missions (no "next" — the daemon stopped).
- `handleAutonomousMissionEnded` and `handleAutonomousMissionFailed` refresh the inspector so the final criteria state lands before the user clicks away.

Backend untouched — the `autonomous_mission_roadmap` WS handler already serves any intent_id whose roadmap.md is on disk.
