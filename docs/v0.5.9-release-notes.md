# v0.5.9 — quality of life + observability

**Date:** 2026-05-04
**Predecessor:** [`docs/v0.5.8-release-notes.md`](./v0.5.8-release-notes.md)
**Theme:** the "is it stuck?" / "what is it costing?" / "why did it stop?" diagnostics, plus a graceful Pause that's distinct from abrupt Stop. Five focused alphas; no field-finding driving them — these are the QoL improvements that make multi-hour autonomous missions actually pleasant to run.

## TL;DR

- **a1: live daemon activity inspector.** Daemon emits `autonomous_activity` events at every phase boundary (picking → dispatching → waiting_dispatch → reflecting → tick_pause → parked). Badge shows `running REFLECT · 12s` in real time. Solves "is it stuck or just slow?"
- **a2: per-iter cost + model attribution.** Each iter card gets a footer with `cost $0.0473 · 12.8k in / 2.1k out` and per-model breakdown chips. Surfaces v0.5.8a1's per-specialist routing as a visible split.

No more parsing summary prose to find which criterion blocked.
- **a4: pause-after-current-iter.** New Pause button next to Stop. Pause = graceful (finish current iter, then exit). Stop = abrupt (cancel in-flight tool calls). Distinct affordances.
- **a5: diagnostics ZIP enrichment.** Bundle now includes `costs.json`, per-iteration metadata files, and a `mission-summary.json` index. Multi-hour mission failures are dramatically easier to triage post-mortem.

## a1: live daemon activity inspector

The chat-header badge previously showed iter count + elapsed time + cost — none of which answered the real question users ask after a long pause: **"what is the daemon doing right now?"**

The daemon now tracks an `_activity` dict (phase + detail + specialist + started_iso + iter_count) and emits `autonomous_activity` events at every phase transition. Six production phases:

| Phase | Meaning |
|---|---|
| `picking` | loading roadmap, choosing next item |
| `dispatching` | starting a sub-mission |
| `waiting_dispatch` | sub-mission running (the long-blocking phase) |
| `reflecting` | full REFLECT pass |
| `tick_pause` | between iterations |
| `parked` | waiting for human-decision-required response |

Frontend renders `Currently: running sub-mission · 47s` in the badge. Updates every second from a client-side `started_at` epoch so elapsed-on-phase ticks live without re-fetching.

**8 new tests** covering `_set_activity` emit/silent modes, `state_snapshot` includes activity (and returns a copy, not a live reference), happy-path phase sequence, parked-phase emission on decision_request.

## a2: per-iter cost + model attribution on iter cards

After v0.5.8a1's per-specialist Ollama routing shipped, the flat session-level cost number stopped being useful — pro for REFLECT and flash for IMPLEMENT meant a single iter mixed cost profiles invisibly.

New `AutonomousIterCostTracker` is a thread-safe per-iteration accumulator. Lifecycle:

```
on_iteration_started(intent, iter)         → opens a bucket
record_status(intent, model, in, out, cost) → adds tokens (per status event)
on_iteration_finalized(intent, iter)       → closes + returns IterCostSnapshot
```

Wired through two layers:

1. The chat-stream `status` event handler routes its `(model, in_tok, out_tok, cost)` into the tracker keyed by the active autonomous intent.
2. The autonomous-event forwarder opens/closes buckets at iter boundaries and emits `autonomous_iteration_cost` after each close, with per-model breakdown.

Frontend attaches the cost data to the matching iter card's footer:

```
cost $0.0473  · 12.8k in / 2.1k out
[deepseek-v4-pro:cloud  $0.0420]  [deepseek-v4-flash:cloud  $0.0053]
```

Per-model chips only show when 2+ models contributed (multi-model = the v0.5.8a1 routing case worth surfacing). Sorted by cost descending.

**14 new tests** for the tracker (lifecycle, per-model attribution, payload sorting, eviction, edge cases, multi-intent isolation, 10-thread concurrency stress test).

## a3: verdict-override provenance on reflection cards

Pre-v0.5.9 the cross-check (model says `satisfied` → roadmap.is_converged()=False → daemon downgrades to `continue`) appended a string note to `outcome.summary` but didn't structure the provenance. Users had to parse prose to figure out which criterion blocked.

New structured fields on `autonomous_reflection`:
- `model_verdict` — what REFLECT actually claimed
- `verdict` — what the daemon ended up with (after override)
- `verdict_overridden` — bool
- `override_reason` — one-line phrasing with singular/plural counts
- `unpassed_criteria` — list of `[type] text — evidence` strings, capped at 200 chars each

Frontend renders a yellow-warn block at the top of the reflection card body when `verdict_overridden`:

```
⚠ Daemon override
Model said `satisfied` · daemon downgraded to `continue`
Model claimed `satisfied` but 2 blocking criteria still unpassed.
Verdict downgraded to `continue`.
Unpassed criteria:
  - [chrome] click toggle A
  - [chrome] click toggle B
```

**5 new tests** covering override-emits-structured-fields, no-override-when-honest-verdict, no-override-when-blocked, multi-criterion list population, singular/plural phrasing.

## a4: pause-after-current-iter

The Stop button cancelled in-flight tool calls. Many users were afraid to click it for fear of losing work, then sat through unnecessary iters waiting for a clean exit point.

Fix: distinct **Pause** affordance.

| Affordance | Behavior |
|---|---|
| **Stop** | Cancels in-flight immediately. Tool calls killed mid-execution. |
| **Pause** | Sets a flag. Current iter completes naturally. Daemon exits at next top-of-loop. |

Daemon side: `pause_after_iter(message)` sets `_pause_after_iter` (lock-protected, idempotent). `_check_stop_rules` checks the flag AFTER user_stop, time_budget, iteration_cap (so a more-urgent stop wins) and returns `("user_pause", message)`.

Frontend: yellow-warn Pause button next to red Stop button in the badge. Stop copy clarified: "Stop NOW (cancels in-flight)" vs "Pause (finish then stop)".

WS command: new `autonomous_mission_pause` parallels `autonomous_mission_stop`. Echoes `autonomous_pause_scheduled` so the GUI flips the badge state.

**4 new tests** covering in-flight iter completes before pause fires, subsequent iters NOT dispatched, idempotent (first message wins), stop takes priority over pause when both signalled.

## a5: diagnostics ZIP enrichment

The Help → Save Diagnostics bundle was useful for chat-session debugging but sparse for autonomous-mission triage.

Three additions:

1. **`costs.json`** at the bundle root. Tells the triager whether the user was hitting their daily budget alert when the issue happened. Redacted as defense-in-depth.

2. **Per-iteration metadata files** under `intents/<hash>/<intent>/iterations/iter-*.json`. Each iter records model + verdict + duration + item_id. Capped at `LATEST_N_ITERS_PER_INTENT` (30) to keep bundle size bounded for long missions. Empty iter files filtered out.

3. **`mission-summary.json`** at the bundle root. Quick-reference index of included intents (project_hash, intent_id, audit_bytes, audit_mtime_iso, iter_files_included, latest_iter_mtime_iso). Triager can read this without unzipping anything else.

Bundle now graceful for missing data: no iterations/ subdir → zero iter files reported, no costs.json → silently skipped.

**8 new tests** covering each enrichment + missing-data fallback paths + the per-intent iter cap.
