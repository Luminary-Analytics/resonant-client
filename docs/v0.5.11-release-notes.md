## a1: event_log.py coverage deepening

`EventLogger` is the JSONL session-event sink that backs debugging, replay, audit trails, and the diagnostics ZIP. Pre-v0.5.11 only the init path was tested (50% line coverage); the actual write path, `replay()`, and `cleanup_old_logs()` were entirely untested. A silent regression in any of those would have shipped invisibly until someone tried to debug a session by reading the JSONL log and discovered missing/duplicated/misformatted entries.

[tests/test_event_log.py](../tests/test_event_log.py) ships 30 tests across 5 classes:

- `TestEventLoggerInit` (6): disabled flag skips file creation, custom + default `log_dir`, unknown `session_id` falls back to `"unknown.jsonl"`, open-failure disables the logger gracefully, str/Path acceptance.
- `TestEventLoggerLog` (8): JSONL line format, timestamp + session_id enrichment, event-field-overrides-enrichment behavior, `default=str` for non-serializable values (e.g. `Path`), no-op when disabled or file is None, periodic-flush counter (every 5 events), write-failure tolerance.
- `TestEventLoggerClose` (3): clears file handle, idempotent on re-call, `__del__` calls close cleanly without raising.
- `TestReplay` (5): yields events in order, skips invalid JSON lines, skips blank lines, missing file returns empty iterator, str path accepted.
- `TestCleanupOldLogs` (8): removes dirs older than retention, keeps recent, gracefully skips non-date dirs, missing base dir returns 0, empty dir returns 0, default retention is 7 days, str path accepted, skips top-level files (e.g. `.DS_Store`).

Coverage delta on `resonant_client/engine/event_log.py`: **50% → 100%**.

## a2: compression.py coverage deepening

Compression fires when conversation history grows past the per-model context budget. [tests/test_compression_budget.py](../tests/test_compression_budget.py) covered the budget-resolution helper (`model_context_budget`) but not the actual compression lifecycle: `estimate_tokens` (list-content branch), `_extract_text`, `_build_summary_prompt`, or `compress()` itself. A regression in any of those would corrupt summaries silently, and the bug only surfaces after `KEEP_RECENT_TURNS+` user messages have accumulated mid-mission — exactly the kind of slow-burn defect that's hard to catch in normal testing.

[tests/test_compression_lifecycle.py](../tests/test_compression_lifecycle.py) ships 31 tests across 4 classes:

- `TestEstimateTokens` (7): empty history, string content at 4 chars/token, list-content text parts counted, mixed entries summed, list with non-dict parts skipped, dicts without `text` field count 0, missing `content` field counts 0.
- `TestExtractText` (6): string returned as-is, list joins text parts, skips non-text types (e.g. `image_url`), skips non-dict parts, `str()` fallback for other content types, missing `content` returns empty.
- `TestBuildSummaryPrompt` (10): user/assistant prefixes, `tool_call` uses `name` field, `tool_result` truncated to 500 chars, long user text truncated to 2000 with `...` ellipsis, empty text skipped, unknown roles silently skipped, summary prompt includes the instructions header, list-content entries get extracted and rendered, empty-content `tool_call` skipped (the `if not text: continue` guard fires before role branches).
- `TestCompress` (8): returns history unchanged when too short / under threshold (with backend NOT called), compresses when over threshold (backend called once with summary prompt), keeps recent N user turns, summary-failure returns original, empty/whitespace summary returns original, explicit `backend` arg overrides session backend, `model_name` kwarg resolves the per-tier threshold so a tiny flash budget trips compress despite a huge `max_tokens` override.

Coverage delta on `resonant_client/engine/compression.py`: **37% → 99%** (only the `split_idx <= 2` defensive guard at line 188 remains uncovered; hard to trigger naturally without a hand-constructed history shape).
