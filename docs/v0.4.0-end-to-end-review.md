Six releases in two days, then a deliberate subtractive release that took the codebase from ~28k to ~26k lines while sharpening the product story.

## The throughline

v0.3.0 → v0.3.5 was a feature-build arc: ship the Mission flow, harden it as real bugs surfaced (Bug #25 was the keystone), close architectural gaps as they exposed themselves. Each release shipped because the previous release surfaced concrete user pain (the Vampire Survivors mission burning 24 tool calls on a scavenger hunt is the prototypical example).

v0.4.0 was a pivot. The Tier-1 mission test on claude-code:sonnet revealed that **the v0.3.5 features didn't even apply** to that backend — claude-code uses its own native tools, bypassing our engine dispatch entirely. `await_user` couldn't be called; cycle guards couldn't fire. The user's response — "we can remove claude and code and all the other models" — was the right one: stop pretending to be a meta-tool, become the best version of one specific thing. **Anthropic users have Claude Code; OpenAI users have Codex; DeepSeek/Ollama users have Resonant Client.**

## What's working well

**The Mission flow is a real product.** The grill-me interview pattern (one question at a time with recommendations) produces specs that are concrete enough to dispatch. Tested with Sonnet and deepseek-flash; both produced valid `## Final spec` blocks. The v0.3.3 project picker means the agent always writes where the user expects.

**The cycle guards (v0.3.3) are the right shape.** Sliding-window signature dedup catches the looser pattern that strict trailing-identical doom loop misses. Read-only churn cap catches "agent only looks, never builds." Both abort cleanly with friendly messages. Layered defense.

**`working_subdir` propagation (v0.3.5) closes Bug #25 properly.** Real architectural fix: when implement #1 scaffolds into `web/`, sibling implement #2 inherits that as its `cwd` instead of starting back at the project root. Tests pass; semantics are right (refines, never regresses).

**Diagnostics ZIP (v0.3.4) is the killer feature for support.** 27-file bundle, redacted, ~33 KB. When a user hits a bug they click two things and have a complete audit log to attach to a GitHub issue. Phase-1 of the log-shipping story is now done; Phase-2 (opt-in Sentry) becomes much less urgent.

**`await_user` (v0.3.5) is architecturally honest.** Synchronous callback, threading event, mirrors the existing permission flow. Tested end-to-end via Chrome MCP — chip-click and free-text reply paths both work.

**v0.4.0 cut was disciplined.** No partial cuts (no "let's keep MLX just in case"), no weasel-room. Single backend, single trust path, single tuning target. The codebase is meaningfully simpler.

## What needs work

**The grill-me prompt is generic.** The `_GRILL_ME_BASE_PROMPT` was written before we knew DeepSeek's specific behaviors. Tier-2 of the deepseek-harness backlog has prompt-tuning items but they're not done. Right now flash/pro both "happen to work well" — we haven't proven it's tuned.

**The cycle-guard thresholds are guesses.** `CYCLE_WINDOW=12, CYCLE_WINDOW_REPEAT=3, CHURN_LIMIT=14` — picked from intuition, no telemetry to back them up. T2.4 in the roadmap proposes per-model thresholds. Real evals (T3.1) would tell us what the right values are.

**Specialists rarely call `await_user`.** The tool exists; the prompts don't push it. The model has to know to call it from the description alone. T2.5 / T2.6 in the roadmap address this — prompt nudges plus a "you're cycling, try await_user" injection.

**No real-mission validation post-v0.3.5.** Every release was tested unit-level + Chrome MCP UI-smoke. The actual end-to-end "run a multi-specialist mission to completion on flash" test was started during v0.3.5 verification but timed out (the strategic pivot hit before it finished). T3.1 — the eval harness — is the missing empirical loop.

**The `select_harness_*` family in `gui/app.py` is over-engineered for a single-backend world.** v0.4.0 simplified the bodies but kept the function shape (multi-role / forced-backend / forced-model overrides). Some of the env-var override surface is now meaningless since there's only one backend type to override to. T5.x in the roadmap covers the cleanup.

**Mac Studio default URL is the right default but isn't probed-fallback-aware.** `resolve_ollama_url` returns 10.0.0.133 unconditionally if no override is set. If 10.0.0.133 is unreachable, the welcome wizard takes over — but a "Try localhost" quick-button (T1.2) would be a nice fallback for dev users.

## Open architectural questions

- **Should the harness teacher escalation path stay as deepseek-pro-only, or should it be removed entirely?** Pre-v0.4.0 it escalated to a frontier CLI (Claude Code / Codex). Now it just picks the bigger DeepSeek tier. Maybe the whole concept is dead.

- **Does the Engram integration still make sense?** Cross-session memory was designed for multi-user / multi-project workflows. With the focus narrowed to "individual dev with deepseek," is the indexing complexity earning its keep?

- **Should LM Studio come back?** Some Mac users have LM Studio set up but not Ollama. The Ollama-only story is cleaner but might lose those users. Defer until we hear from one.

- **The Resonant Cognitive Engine integration (cut entirely in v0.4.0)** — was that ever real? The harness story was built around it. Now there's no engine in the picture, but the harness scaffolding remains. Is the harness even meaningful in a single-backend world?

These are real questions. None block the next release.

## Risk register

- **The cut may break users who actually used the multi-backend story.** v0.3.5 stays downloadable on the Releases page; an upgrade-then-revert path exists. Low impact unless we have an Anthropic-using user base we don't know about (we don't).

- **`detect_backends` returning empty when Ollama is up but returns 0 models** is a UX edge case the wizard handles, but I haven't tested that exact "0 models" path end-to-end. Worth a manual smoke on tomorrow's session.

- **`refresh_network_defaults` no longer sets `self.api_url` for Resonant Engine** since that backend is gone. There may be dead-code paths in `app.py` that reference `self.api_url` and will get an empty string now. Worth a grep.

## Tactical observations

- The Edit tool's quirk with Unicode (`✓` vs `✓`) cost ~10 minutes mid-cut. When in doubt, replace via Bash + `sed` or use a placeholder string first.
- The 30-second `preview_eval` timeout means long polling loops need to stay under that. Polling in 28s windows worked.
- The screenshot timeout once during the v0.3.5 mission test — recovered by polling DOM via eval. The Chrome MCP preview path is solid but not bulletproof.
