# Resonant Client v0.13.2

This patch restores reliable tool calling and makes browser ownership visible
again after reconnecting to an existing Chrome session.

## Reliable tool calls

- Kimi requests no longer fail when a saved session contains overlapping tool
  catalogs. Resonant removes duplicate declarations at the provider boundary,
  so Retry and Continue also recover tasks that were already affected.
- Newly loaded tool catalogs no longer save the same definition twice.
- Built-in tools keep precedence if an MCP server exposes a conflicting or
  legacy unprefixed name.

## Browser and computer-use identification

- Resonant's dedicated Chrome profile reloads and rediscovers its grouping
  extension when the app reconnects to a browser that survived an app restart.
- Fresh extension workers are allowed to finish starting before the first tab
  group is configured, removing the intermittent missing-group race.
- The active Chrome tab is placed in an expanded purple group named for the
  Resonant session.
- Built-in browser actions and MCP browser/computer actions show the same
  purple activity glow on the monitor containing the active window.
- Computer use retains the soft purple cursor halo and multi-monitor borders.

## Validation

- The previously failing saved session was replayed with one declaration per
  provider-visible tool name.
- The Chrome grouping path and computer-use indicators were verified live on
  Windows.
- The full suite passes: 3,053 tests, with 2 platform-conditional skips.
