# Resonant Client v0.11.8

Long-running sessions: a bricked-session fix, readable failures, notifications
when a run needs you, and a bounded wait when it does.

## Sessions no longer become permanently unusable

- Fixed a failure where a session could reach a state that every later request
  was rejected from. When a turn was cancelled or died mid-dispatch, the
  assistant message announcing its tool calls was kept while the results never
  arrived. That orphaned call was replayed on every subsequent request, so the
  provider rejected the turn with a 400 forever — Retry and Continue reproduced
  it identically, and only starting a new session escaped it.
- Every declared tool call is now answered exactly once. An interrupted call
  receives an explicit "the run was interrupted" result rather than being
  dropped, so the model can re-run the tool instead of assuming a result it
  never received.
- Applies to both the Kimi and EXO providers.

## The whole error, not the first line of it

- A failed turn showed one clipped line ending in an ellipsis, with no way to
  read the rest. Provider errors state the violated constraint at the end of
  the sentence, so the clipped part was the diagnosis.
- Failures now carry an expandable, copyable block: collapsed by default,
  wrapped and scrollable when open, one click to copy for a bug report. The
  one-line summary is unchanged where it belongs.
- Multi-line errors no longer collapse into a single run-on line.

## Notifications for unattended runs

- Desktop notifications when an autonomous session completes, fails, or parks
  waiting on a decision. Previously nothing reached you outside the window,
  which is the one thing you cannot rely on during a forty-minute run.
- Silent while the window is focused — an alert for something already on screen
  is noise. Permission is requested when you start autonomous work rather than
  at launch.

## A bounded wait when a run needs you

- Choose at launch how long a session may sit waiting on your decision: **Wait
  for me** (the default, unchanged), 15m, 30m, 1h, or 4h. Previously a parked
  session waited forever, so an unattended run could park early and do nothing
  for hours — indistinguishable from healthy work.
- On expiry the session proceeds with the option it nominated, recorded as an
  automatic decision so the history never implies you made it. A decision with
  no acceptable default stays parked rather than being guessed at.
- The choice is stored with the session, so a session resumed after a crash
  keeps the deadline you set instead of reverting to waiting forever.

## Interrupted work can be restarted

- An agent whose run was cut short by a restart or crash can now be re-run from
  its saved assignment, via a Restart control on the agent. Previously its
  assignment survived but nothing could act on it, so a worker killed near the
  end of a long run was simply lost.
- The retry is told what its predecessor already completed, so it inspects the
  workspace before repeating anything. The interrupted run is preserved and
  still readable rather than being overwritten by its own retry.
- Restarting an agent that finished successfully is refused; there is nothing
  to redo.

## Long sub-tasks are no longer killed for being slow

- The ceiling on a single sub-task now scales with the session's time budget
  instead of being a fixed hour. That fixed value was wrong at both ends: on a
  one-hour session it allowed a single sub-task to consume the whole budget,
  and on a multi-day session it cancelled legitimately long work such as a
  large test suite or a slow build. Two such cancellations stopped the entire
  session.

## Validation

- Full Python suite: 2,875 passed, 2 platform-skipped. Ruff clean.
- Interface behaviour verified against a running server: the launch card, the
  expandable error block, notification delivery and suppression, and the
  Restart control's availability per agent state.
