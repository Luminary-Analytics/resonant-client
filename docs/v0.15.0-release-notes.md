# Resonant Client v0.15.0

This release improves open-model reliability and makes building, previewing,
and checking projects easier to follow.

## Building and checking projects

- Managed previews keep development servers running between turns, with
  readiness checks, logs, and an explicit stop control.
- Named checks report the command, requirement, and actual result. Failed
  checks stay visible, and subsequent edits mark earlier results as stale.
- Completion cards show distinct changed files and only mark named checks as
  passed when their recorded evidence is current.
- Project navigation and session titles update immediately. Project notes and
  preview controls are accessible from the conversation toolbar.

## Open-model reliability

- Kimi supports low, high, and max reasoning effort, persisted per session,
  with progress updates while the provider is generating a response.
- Stricter tool-call recovery reduces accidental execution of text that merely
  resembles a tool call.
- Context budgeting accounts for tool arguments, schemas, reasoning, retrieval,
  and images. Compression preserves constraints and evidence more reliably.
- Archived tool output remains available through artifact retrieval.

## Project knowledge and skills

- Project notes have editable sources and confidence labels. Notes tied to
  changed source files are marked stale and excluded from automatic recall.
- Browser and transaction acceptance skills guide realistic user journeys and
  failure checks, including keyboard use, persistence, and concurrency.
- Skill descriptions load within a bounded context budget; full instructions
  are retrieved on demand. Project policy can suppress skills or global pins.
- Evaluation mode excludes personal global skills and remote memory recall.

## Validation and limits

- Automated suite: 3,133 passed, 2 skipped.
- Browser regression covered project switching, check failures, preview
  readiness and shutdown, reasoning settings, and note editing.
- Earlier live Kimi evaluations covered a CLI utility, browser task board,
  and transactional stock application. These were individual runs, not a
  repeated model benchmark.
- Check freshness tracks files changed in the turn, not every dependency.
  Project notes are sourced assertions, not independently verified facts.
