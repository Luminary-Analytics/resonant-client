## a2: cross-feature integration tests

Each v0.5.8 + v0.5.9 feature has its own unit-level coverage, but the *interactions* between them weren't tested anywhere. A real multi-hour mission with a human-in-the-loop fork hits all four (pause, decision-request, verdict-override, activity inspector) on a single iter — and the failure mode in those interactions is exactly the kind of thing the linux-bridge field run barely missed.

Three test classes, 7 tests in [tests/test_v0_5_10_cross_feature.py](../tests/test_v0_5_10_cross_feature.py):

**TestPauseDuringDecisionPark** — v0.5.9a4 × v0.5.8a2:
- `test_pause_does_not_unblock_park`: a `pause_after_iter` request while the daemon is parked waiting for a human decision must NOT unblock the park (only `provide_decision` or `stop` does that). Confirmed by signaling pause during park and verifying the daemon thread is still alive.
- `test_decision_then_pause_completes_iter_then_exits`: queue pause during park, provide decision, daemon resumes, completes iter, exits cleanly with `stop_reason="user_pause"` at next top-of-loop. Both decision events fire.
- `test_stop_during_park_overrides_queued_pause`: stop wins even with pause already queued — daemon wakes (because `stop()` explicitly sets `_decision_event`), exits as `user_stop`, no `decision_received` event.

**TestActivityPhasesAcrossDecisionFlow** — v0.5.9a1 × v0.5.8a2:
- `test_parked_phase_emitted_with_question_detail`: parked activity event fires once with `specialist=reflect` and detail truncated from the question string. `state_snapshot` mirrors.
- `test_no_parked_phase_when_no_decision_request`: negative case — ordinary continue verdict goes through `picking → reflecting` but never emits `parked`.

**TestOverrideAfterDecisionPath** — v0.5.9a3 × v0.5.8a2:
- `test_decision_then_lying_satisfied_triggers_override`: full lifecycle where REFLECT parks, user picks, REFLECT re-runs claiming `satisfied` on a still-unpassed chrome criterion. Both `decision_required` AND `decision_received` events fire, AND the `autonomous_reflection` event has the v0.5.9a3 structured override fields populated (`model_verdict=satisfied`, `verdict=continue`, `verdict_overridden=True`, `override_reason` with phrasing, `unpassed_criteria` including the chrome line).
- `test_no_override_when_post_decision_verdict_is_continue`: negative case — honest `continue` post-decision doesn't trigger the override path.

These are NOT redoing what unit tests already cover; they assert that multiple features fired together produce the right combined event sequence — which is what the GUI consumes during a real run, and what the cost tracker / forwarder / sidebar all key off.

## a3: smoke runner edge-case hardening

Two unprotected defensive contracts in `resonant_client/smoke/runner.py`:

**1. seed_files path safety.** `make_fresh_project(seed_files=...)` previously trusted dict keys verbatim. A spec-author typo with `..` or an absolute path would silently write outside the smoke project tempdir. On POSIX `Path('/proj') / '/etc/x' == Path('/etc/x')`, so `seed_files={"/etc/passwd": ...}` would have resolved to the real `/etc/passwd`. Bundled specs are trusted; this is defense in depth.

Two-stage validation now lives module-level for testability:

- `_check_seed_path_format(relpath)`: cheap pre-tempdir check. Rejects empty/non-string, OS-absolute, POSIX-rooted-on-Windows (`/foo` resolves to `C:\foo` on Windows but isn't OS-absolute there), and any `..` segment. Critically, runs BEFORE `tempfile.mkdtemp` so a bad spec doesn't leak a stale tempdir per failed validation.
- `_validate_seed_path(relpath, project_root)`: full check — runs the cheap checks PLUS verifies the resolved path is inside the project root via `target.relative_to(project_root.resolve())`. Catches anything sneaky (e.g. paths that pass the cheap check but resolve outside via path canonicalization).

**2. iter_durations zero-pollution.** Pre-fix:

```python
dur = payload.get("duration_seconds", 0)  # missing → 0
if isinstance(dur, (int, float)):          # 0 passes
    summary["iter_durations"].append(float(dur))  # 0.0 lands
```

A daemon-event-shape regression that dropped `duration_seconds` would have silently filled the durations list with 0.0 entries — biasing `avg_iter_duration_seconds()` and the variance/baseline rollups downward without any visible failure. Now:

```python
dur = payload.get("duration_seconds")           # missing → None
if isinstance(dur, (int, float)) and dur > 0:   # None / 0 / negative all skip
    summary["iter_durations"].append(float(dur))
```

`_on_event` is also extracted into module-level `_accumulate_event(payload, summary)` and `_new_summary()` so the filter behavior is unit-testable without booting a live mission.

26 new tests in [tests/test_smoke_runner_hardening.py](../tests/test_smoke_runner_hardening.py):
- 8 in `TestSeedFilesPathSafety` covering absolute (POSIX + Windows), `..` segments (leading + middle), empty/non-string keys, accept-cases for simple + nested-subdir paths, and the no-tempdir-on-rejection invariant.
- 5 in `TestValidateSeedPathDirect` for the module-level helper.
- 13 in `TestAccumulateEvent` covering every event kind, every duration-filter case, unknown/empty events as no-op, and a realistic full-iter sequence.
