# v0.5.3 — refine the autonomous loop's UX, codify the dev cycle

**Date:** 2026-05-03
**Predecessor:** [`docs/v0.5.2-smoke-results.md`](./v0.5.2-smoke-results.md)
**Theme:** make the autonomous-mission feature *feel* good for users, and bake the inner-loop dev cycle into the product so future iteration stays as fast as v0.5.0-v0.5.2 was.

---

## TL;DR

v0.5.0-v0.5.2 proved autonomous missions converge reliably (4 of 5 pro runs converged on first try, all bugs found became regression-tested fixes). v0.5.3 turns that into a feature you can actually live with:

- **Resume after interruption** — server restart / app crash / laptop sleep no longer means losing 4 hours of mission work.
- **Roadmap visible at a glance** — sidebar inspector shows criteria progress + next item + latest reflection without opening `roadmap.md`.
- **Smoke harness as a first-class CLI** — `resonant-smoke variance --spec wordcount --model pro --n 3` replaces three throwaway scripts and produces ship-readiness signals on demand.

All four alphas land with regression tests; the full suite is **1503 pass / 2 skip**.

## What shipped, alpha by alpha

### a1: backend resume + orphan detection

Two new functions in `gui/autonomous_session.py`, plus a refactor that pulls daemon construction out of `start_autonomous_mission` into a private `_spawn_autonomous_daemon` helper.

- **`resume_autonomous_mission(state, intent_id, on_event, image_provider)`** — loads the existing roadmap from disk, validates it has criteria, refuses to double-spawn, then constructs a fresh daemon. Preserves checked items, validated criteria, and the iteration log. Time budget timer resets on resume (not back-dated).
- **`find_orphaned_autonomous_missions(state)`** — scans the project's sessions for `mission_state.phase == "autonomous_running"` whose `intent_id` isn't in the live `_autonomous_daemons` registry. Returns enough metadata for the GUI to surface a "Resume" affordance per orphan.

Tests: 5 for resume, 9 for orphan detection. All edge cases (missing roadmap, no criteria, double-spawn, finished daemon, missing intent_id, stale registry entries) covered.

### a2: WS commands + orphan banner UI

The backend resume from a1, surfaced to the user.

- **`init` payload extended** — every WS connect now includes `autonomous_orphans` so the banner renders immediately, no extra round trip.
- **`autonomous_orphans_list` command** — explicit refresh from the frontend.
- **`autonomous_mission_resume` command** — switches to the originating session (if `session_id` provided), recreates the backend, calls `resume_autonomous_mission`. Surfaces ValueError ("no roadmap" / "no criteria") and RuntimeError ("already running") as user-facing errors with a refreshed orphan list.
- **Banner UI** — above `chat-messages`. Each card shows feature name, age (formatted "Started X ago"), Resume button, Dismiss button. Resume disables itself + flips text to "Resuming…" to prevent double-click races. Roadmap-missing orphans get a disabled Resume with an explanatory tooltip.

The Dismiss action is local-only by design — it's a "not now" gesture, not a "permanently forget about this".

### a3: sidebar roadmap inspector

The chat-header autonomous badge tells you *that* a mission is running; the new inspector tells you *why convergence isn't yet there*.

- **`build_roadmap_inspector_payload(intent_id, roadmap, roadmap_path)`** — pure function. Marshals a parsed Roadmap into a JSON-friendly dict. Acceptance criteria carry `is_blocking` so the frontend renders `[manual]` items as advisory rather than gating.
- **`autonomous_mission_roadmap` WS command** — re-parses `roadmap.md` from disk on every request (REFLECT mutates it asynchronously, no caching). Calls the helper.
- **Sidebar inspector UI** — slot above the agent list. Hidden when not in an autonomous mission. Renders feature title, criteria-met pill (green when converged), per-criterion list (✓ pass / · pending / ✗ fail / ○ manual), the next unchecked item, and a trimmed reflection summary.
- **Refresh triggers** — wired into autonomous_iteration_complete, _failed, _reflection (all of which mean REFLECT just touched the roadmap), plus autonomous_mission_started + session-switch via `_syncMissionUI`. "Bootstrapping…" placeholder shows when the daemon hasn't yet persisted the roadmap.

Tests: 13 for the payload helper covering criteria states, manual non-blocking flag, next-item logic, iteration-count rollup, reflection trimming.

### a4: smoke harness CLI + variance comparison

The big one for ongoing dev velocity. v0.5.0-v0.5.2 surfaced parser bugs ONLY because we ran wordcount four times by hand. v0.5.3a4 makes that cheap.

New package: `resonant_client.smoke`

- **`specs.py`** — three bundled specs (`minimal`, `wordcount`, `roguelite`), all pre-validated to parse via `extract_spec`. Add new ones here rather than scattering markdown across one-off scripts.
- **`runner.py`** — `run_smoke(spec_name, model_label)` returns a `SmokeResult`: verdict, iter durations, stop reason, project + roadmap paths. Encapsulates the stub AppState + tempdir bootstrap that every smoke script was duplicating.
- **`variance.py`** — `run_variance(spec, model, n)` returns a `VarianceReport`: convergence rate, per-run timing distribution (median/min/max/stddev), pooled iter-duration stats across all runs, stop-reason breakdown for non-converging runs. Median + stddev helpers are pure functions, unit-tested.
- **`cli.py`** — `resonant-smoke` entry point with three subcommands:
  - `list-specs` — print the registry.
  - `run --spec X --model Y` — single mission. Exits non-zero on non-convergence so CI gates on it.
  - `variance --spec X --model Y --n 3` — N runs, report + JSON artifact. Exits non-zero unless every run converged.

Registered as a project script (`resonant-smoke` available after install). Default record path is `./smoke-runs/<prefix>-<ts>.json` so records show up in `git status` next to whatever was being tested.

Tests: 32 covering registry, SmokeResult, statistics, VarianceReport, CLI parser. Live runs (which need Ollama) are gated on the explicit CLI invocation.

## Why this matters

The user request that drove v0.5.3 verbatim:

> the goal now we have for the most part, achieved a measure twice cut once approach. Is to refine the process so that it works seemlessly and easily for the front end user. Also it needs to be seemless to continue to easily and quickly enhance the product/project in an on going basis.

Two distinct asks, both addressed:

**Frontend UX** — the `[autonomous mission]` feature now degrades gracefully on common failures (a1 + a2: resume), and gives the user real visibility into mission state without leaving the chat (a3: inspector).

**Dev cycle ergonomics** — `resonant-smoke variance` (a4) means we can answer "is pro still the right default?" or "did this parser change break wordcount?" in 5 minutes instead of an afternoon of manual ssh-in-and-run-script.

## What's NOT in v0.5.3

Deliberately kept out of scope:

1. **Cross-model comparison** in `resonant-smoke compare` — `variance` covers same-model variance; cross-tier benchmarking is a separate workflow that benefits from being a different command shape (multi-axis output). Defer to v0.5.4 if there's demand.
2. **Markdown report output** from variance — JSON is sufficient for the inner-loop check; markdown summaries can be hand-written from the JSON when shipping a release-notes doc.
3. **Sidebar inspector for COMPLETED missions** — currently inspector hides when phase isn't `autonomous_running`. A "show me the historical roadmap for a paused/done mission" affordance would be nice; deferred.
4. **Live walker-retry validation** (carried from v0.5.2 backlog).
5. **kimi-k2.6 / glm-5.1 / minimax-m2.7 PLANNER_BY_TIER entries** (carried from v0.5.2 backlog).
