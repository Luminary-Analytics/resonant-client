# Lumi 0.20.0-alpha.1

The first open alpha of **Lumi**, the desktop coding agent by Luminary
Analytics. Lumi was called SONN Client, and before that Resonant. This is the
first release under the new name and the first under Lumi's commercial
license.

Lumi works in a project folder on your computer. You describe a change; the
agent reads the code, edits files, runs commands and checks, and shows what it
did and what passed. It uses the models you choose, under your own accounts.

**This is an alpha.** It's for developers who are happy to try early software
on code they can review and undo, not for production-critical work. Windows
comes first; the macOS build is a preview. Neither build carries Luminary's
publisher signature yet, so Windows and macOS warn before the first launch
(see [Installing](#installing)). Lumi is free for individuals during the
alpha. Features marked **preview** are unfinished and may change.

## Try this first

1. **Install and accept the terms.** When Lumi opens, it shows its End User
   License Agreement and the Alpha and Beta Test Terms, with a link to the
   privacy notice. It sends nothing to a model until you choose **Accept**.
2. **Connect a model** from the checklist in the empty chat, or in Settings:
   an Anthropic, OpenAI or OpenRouter key (**Settings › API keys**), your
   ChatGPT subscription through the Codex CLI (**Settings › Connections ›
   Sign in with ChatGPT**), your Claude subscription through the Claude Code
   CLI (install and sign in to it, then pick its models), or a model on this
   computer through Ollama (**Settings › Connections**, the Ollama card's
   **Test** and **Save**).
3. **Open a project**, or choose **Try the sample project** (a small Python
   program with a planted bug), then **Use a suggested task**. Watch the
   **Evidence** group for what the agent read and ran, review the changed
   files, and open **Timeline** in the chat header to restore a checkpoint.
4. **Try Team (preview)** in a Git project, with an OpenRouter, Ollama or
   other OpenAI-compatible model: type `/team` and an objective, turn on
   **Enable team preview** in the panel that opens, check the limits, and
   press **Start orchestrated team**. Workers only read unless you also turn
   on **Allow scoped file changes**.
5. **Tell us what happened:** see [Feedback](#feedback).

## Installing

### Windows

Download `lumi-setup-0.20.0-alpha.1.exe` from the
[GitHub release](https://github.com/Luminary-Analytics/resonant-client/releases/tag/v0.20.0-alpha.1)
or [Luminary's update site](https://luminary-analytics.github.io/resonant-client/downloads/v0.20.0-alpha.1/lumi-setup-0.20.0-alpha.1.exe).
The [download page](https://luminary-analytics.github.io/resonant-client/)
links stable releases only, so it doesn't list this alpha.

The installer isn't signed with a Windows publisher certificate yet; Luminary's
code-signing account is still being set up. So:

- Your browser may warn that the file isn't commonly downloaded. Keep it.
- Windows SmartScreen may show **Windows protected your PC**. Choose **More
  info**, check that the app is `lumi-setup-0.20.0-alpha.1.exe`, then choose
  **Run anyway**.
- The installer asks for administrator rights, because Lumi installs for all
  users in `Program Files\Lumi`. Windows shows its publisher as unknown.
- Its license page shows the agreement and the test terms; setup goes on once
  you choose **I accept the agreement**. Lumi still asks each person to accept
  them when it opens.

Updates that Lumi downloads later are checked against Luminary's signing key,
which is built into the app, before they install. That update signature is
separate from the Windows publisher signature this build doesn't have.

### macOS (preview)

1. Download `lumi-0.20.0-alpha.1.dmg` from the
   [GitHub release](https://github.com/Luminary-Analytics/resonant-client/releases/tag/v0.20.0-alpha.1)
   or [Luminary's update site](https://luminary-analytics.github.io/resonant-client/downloads/v0.20.0-alpha.1/lumi-0.20.0-alpha.1.dmg).
   It needs an Apple silicon Mac with macOS 12 or later.
2. Open it and drag **Lumi** to **Applications**, then open Lumi from
   Applications. A copy run from the disk image can't update itself.
3. The build isn't notarized by Apple yet, so the first time macOS says it
   can't check Lumi for malicious software and doesn't open it. Choose
   **Done** (not **Move to Trash**). Open **System Settings › Privacy &
   Security**, scroll to **Security**, and choose **Open Anyway** beside the
   message about Lumi. Enter your password, then choose **Open Anyway** once
   more. You do this once on each Mac. See
   [Lumi on macOS](macos.md#opening-a-build-that-isnt-notarized).

### Getting the next alpha

Alpha builds go only to the beta update feeds; there is no separate alpha
channel. A new installation starts on the **Stable** channel, which takes only
stable releases, so it won't be offered the next alpha by itself. To get later
alphas automatically, choose **Settings › Updates › Channel › Beta** and
restart Lumi. Lumi then checks once a day, and **Check for updates** in that
page (or **Help › Check for Updates…**) checks at once. An update doesn't
install while an agent turn is running. See [Updates](updates.md).

## Highlights

### A coding agent that finishes the job and shows its evidence

- Each turn's **Evidence** group lists what the agent read, searched and
  checked. Every item settles to its own result, and the group counts
  failures and refusals ("1 failed", "2 not run"). A call that was refused
  says why, in the app and in the terminal UI, instead of a bare "denied".
- **Changed files** counts only edits that were applied. An edit that was
  rejected, blocked, failed or stopped no longer counts, and a worker's
  hand-off lists only its successful changes and the checks that ran.
- A run's **Trace**, at the end of its card's work details, lists its steps,
  tool calls, model calls with their tokens, and checkpoints. It opens after a
  reload and saves as OpenTelemetry JSON. Outputs over 50,000 characters and
  screenshots are kept under **Saved**.
- Each turn's footer names its own model and token counts.
- `/plan` works again (it had started nothing since July 27). A plan can be
  paused, resumed and stopped from the Plan tab, also after a reload, and its
  steps report under its card instead of as turns of the conversation.
- It works on a new Windows computer: without Git, Python or Node.js,
  sessions start and Lumi says what needs Git. Command output with
  non-English characters reads correctly, and a double-clicked `lumi.exe`
  opens the app.

### Your models, your accounts

- **Anthropic** keys use the Messages API, with extended thinking and prompt
  caching. **OpenAI** keys use the Responses API, and OpenAI isn't asked to
  store the conversation. **OpenRouter** lists its models with tools.
  **Codex** uses your ChatGPT sign-in; if the Codex CLI is missing, Lumi says
  what to install (Node.js, then `npm install -g @openai/codex`). **Claude
  Code** uses its own CLI and sign-in. **Ollama** has a card in Settings ›
  Connections to test and save its address. EXO, Kimi, SONN, Azure OpenAI,
  Amazon Bedrock, Google Vertex AI and your own OpenAI-compatible endpoints
  work too.
- API keys go into the operating system's credential store (Windows
  Credential Manager, the macOS Keychain), not the settings file. The commands
  and servers the agent starts don't get them. Codex and Claude Code keep
  their own sign-ins.
- **If the model fails, continue with** (Settings › General) retries a failed
  request with a fallback model. **Models for roles** can name sessions with
  a local model, or describe images for a model without vision.
- The getting-started checklist ticks **Connect a model** only when a saved
  connection works.

### Team (preview): an orchestrator running parallel workers

- **Team** puts several workers on one objective. Type `/team` and an
  objective, or open a conversation's Team panel, and turn on **Enable team
  preview**. With **Let the orchestrator run the team**, the conversation's
  model plans the work, dispatches workers for one to eight rounds, answers
  their questions during a round, and writes a final report. **Use in chat**
  attaches the results to your next message.
- Workers read only the folders you allow. Writers change files in their own
  Git worktrees. Their changes wait for you to check and apply them, unless
  you turn on **Apply changes that pass every check**: the orchestrator then
  combines them, runs every check you declared, and applies the result only
  when all pass, as a fast-forward and never over uncommitted work.
- A team the orchestrator runs needs Full-auto. From another mode Lumi asks
  once, for that team only (**Run this team in Full-auto**). You can pause,
  steer or stop a team at any time, and recover and continue one that a
  restart interrupted.
- **Preview limits:** teams run on Ollama, EXO, Kimi, OpenRouter, SONN or an
  OpenAI-compatible connection such as NVIDIA NIM. Anthropic and OpenAI keys,
  Codex and Claude Code can't run a team yet. Teams that change files need
  Git (Git for Windows on Windows). The live runs so far used NVIDIA NIM
  models, and no speedup over a single agent is claimed. See
  [Team preview](swarming.md).

### Safer by default

- **New installations start in Auto-edit:** file edits in the project apply,
  and shell commands and other actions ask first. Existing installations keep
  their saved mode.
- **Full-auto for one run at a time.** Plans, roadmap builds, autonomous
  sessions and orchestrated teams run in Full-auto. From any other mode they
  now ask first, and a yes covers that run only; the audit log records each
  one.
- **Ask asks before each change.** It used to refuse writes and commands
  without asking. Your **Deny** is final.
- **Project trust.** Until you choose **Trust this project**, Lumi doesn't use
  a repository's instructions, notes, allow rules, automatic lint and tests or
  language servers, or run Git when the repository's settings name programs.
- **Checkpoints and undo.** **Timeline** (in the chat header, the command
  palette and the session menu) lists checkpoints. **Restore…** brings back
  the files, the conversation or both, and keeps your current files in a
  recovery archive, or on a `lumi-recovery/…` branch in a Git project.
  **Compare** shows what changed since a checkpoint in a Git project.
- **Guardrails in every mode.** Commands that erase a drive or your home
  folder, format disks or shut the computer down never run. Lumi never runs
  its own tools (Git, search, system tools) from the project folder, and the
  app's local page opens only through a one-time launch link.

## Upgrading from SONN Client or Resonant 0.19.x

- **Install it yourself.** Installed SONN Client and Resonant copies read the
  stable update feed, which doesn't list this alpha. Close SONN Client, then
  run the alpha installer. It removes the SONN Client or Resonant
  installation first, so Apps & Features keeps one entry, **Lumi**.
- **Your folder moves.** At its first launch Lumi moves `~/.resonant` to
  `~/.lumi`, with your settings, sessions and logs. If the move is blocked
  (for example, by an older copy that is still running), Lumi keeps using the
  old folder and tries again at the next launch. After the move, API keys
  saved in `settings.json` move into the operating system's credential store,
  under the name "Lumi".
- **Going back:** SONN Client 0.19.x reads only `~/.resonant`, and keys only
  from its settings file. After Lumi has moved them, an older copy starts
  without your settings, sessions and keys.
- **Old names still work:** the `resonant` commands, `RESONANT_*` environment
  variables, a project's `.resonant/` folder, `resonant-pack.json`,
  `resonant-policy.json` and `RESONANT.md`, and `~/Documents/Resonant
  Projects` as the default projects folder.
- **Update settings start fresh.** WinSparkle's preferences moved to a new
  registry key.
- **The license changed.** This release is under the End User License
  Agreement and, as a pre-release, the Alpha and Beta Test Terms; Lumi asks
  you to accept them at first launch. Copies you have of versions published
  under the MIT License stay under it (see [Legal](#legal)).
- **Your permission mode stays.** Only new installations start in Auto-edit.
  Earlier versions saved Full-auto as the default at their first launch, so an
  upgraded installation usually stays in Full-auto. Change it in **Settings ›
  General › Default permission mode**.
- **Other changes you may notice:**
  - Projects in your Recent projects list are trusted after the upgrade, but a
    repository's `lumi-policy.json` allow rules apply only after you review
    that file once.
  - Your Settings hooks now also run in `lumi run`, scheduled tasks, model
    comparisons and the chat gateway. A gate hook that times out now blocks
    its call; raise its `timeout_seconds` if it's slow.
  - Images from other websites in replies no longer load. Screenshots and
    attachments still show.
  - A bookmark to the app's page needs a new launch link after each start
    (in the desktop window, **File › Open in Browser** makes one).
  - Issue links send GitHub and GitLab tokens only to github.com, gitlab.com
    and the hosts in **Settings › Issue trackers › Your code hosts**; add your
    GitHub Enterprise or self-managed GitLab host there.
  - The codebase index moved to `~/.lumi/projects/<id>/`. An old
    `<project>/.lumi/index.json` isn't read any more and can be deleted.

## Known issues and not yet

- **Feedback isn't sent anywhere yet.** Help › Send Feedback keeps reports on
  your computer until Luminary's feedback service is online. Email
  rich.bellantoni@luminaryanalytics.com instead.
- **Unsigned builds.** Expect SmartScreen on Windows and Gatekeeper on macOS
  until Luminary's Windows code-signing and Apple Developer ID are set up.
- **The next alpha needs the Beta channel.** New installations start on
  Stable and aren't offered later alphas until you switch.
- **Team is a preview.** It isn't available with Anthropic or OpenAI keys,
  Codex or Claude Code. Teams that change files need Git. It has been run live
  only with NVIDIA NIM models, and its checks of a packaged app ran before the
  rename and haven't been repeated. A team that hasn't finished holds its own
  conversation until you stop or finish it.
- **Lumi Cloud isn't hosted yet.** Features for teams and companies are
  labelled in the app but can't be used: the Lumi account, sharing a
  conversation, hand-offs to a teammate, second-person approvals, the review
  queue, the team library, tasks from Slack and Teams, and organization
  oversight.
- **Windows has no shell sandbox.** In Full-auto, shell commands run without
  one. The sandbox is for macOS and Linux, and turning it on in Windows makes
  Lumi refuse commands.
- **macOS is a preview.** No one has yet tried, on a real Mac, the Gatekeeper
  approval of a downloaded build, a whole update, the native window's menus
  and shortcuts, dictation, computer use's permission prompts or the
  Keychain. Computer use's on-screen indicator is Windows-only.
- **Live model runs.** Most changes in this release were checked with
  automated tests and scripted models. Live checks of this build with
  Anthropic, OpenAI, OpenRouter, Codex, Claude Code and Ollama are still to do.
- **Codex and Claude Code run their own tools.** Lumi's approvals, hooks, file
  exclusions, checkpoints, data loss prevention and secret scan don't reach
  the tools inside them, and offline mode refuses them.
- **Computer use is on by default.** The agent's desktop tools take
  screenshots, which go to your model provider, and control the mouse and
  keyboard. Turn them off in **Settings › Privacy & security › Computer use**.
- **Excluded files** are kept from Lumi's file tools and searches, not from
  shell commands.
- **Autonomous sessions** are experimental and off by default. Stopping one
  during a reflect pass on an empty roadmap can end it as "stuck, needs you".
- **Plan activity isn't saved with the conversation.** After a reload the Plan
  tab's **History** keeps its snapshots.
- A call that never ran because the turn was stopped first still shows "…".
- **Accessibility:** the conformance report is a self-assessed draft, and no
  one has tried Lumi with a screen reader yet.
- **Offline mode is a first pass.** It doesn't limit programs the agent runs;
  use a firewall for that.
- **Not in this release:** the MSI for device management (stable releases
  only), Linux packages (built in CI, not published), and the documentation
  site (built, not published).

## Changes since 0.19.1

This release gathers everything since 0.19.1 (September 13, 2026). Each
change's own record, with its date and the checks run on it, is in the
[change record](v0.20.0-alpha.1-change-record.md).

### Security

- **The app's local page needs a launch link.** The desktop server accepted
  any local WebSocket, so another program, another account or a web page
  could run commands through it. Each launch now makes a token, and a page
  gets in only through the one-time link the app opens.
- **Approvals mean what they say.** A Deny could still run the tool. Now only
  an explicit approval runs a call, late or stale answers are ignored, and
  Auto-edit asks before shell, MCP, browser, desktop and Git actions.
- **Capability packs in a repository could approve themselves.** Now only
  your approval of that pack turns it on, pinned to a digest of every file,
  and any change turns it off until you approve it again. Packs can be signed,
  and **Trusted publishers** lists the keys you trust.
- **Lumi's own programs never come from the project folder** (Git, ripgrep,
  system tools, editors, language and MCP servers, the Codex and Claude Code
  CLIs), so a repository's `git.bat` or `explorer.exe` no longer runs. In a
  project you haven't trusted whose Git settings name programs, Lumi runs no
  Git. Clicking a changed file that would run offers **Show in folder**
  instead.
- **Machine policy comes only from places only administrators can write**,
  and a Group Policy `PolicyFile` that can't be read fails closed.
- **Keys and secrets.** API keys move into the credential store. Commands,
  hooks and servers the agent starts no longer receive provider keys. Saved
  key values are removed from tool output, and **Scan for secrets** (Settings
  › Privacy & security, off by default) also removes values that look like
  credentials. Diagnostics remove saved keys. Connections use the operating
  system's certificates and can go through a proxy.
- **Project trust, exclusions and retention.** A `.lumiignore` or excluded
  paths keep files away from Lumi's file tools and searches. Transcripts can
  be deleted after a number of days. Switches turn off Codex and Claude Code,
  computer use or the chat gateway.
- **Guardrails and a shell sandbox.** Destructive commands are refused in
  every mode. An optional sandbox on macOS and Linux lets commands write only
  in the project (off by default).
- **A strict Content-Security-Policy** on the app's page, so markup in a reply
  can't run script.
- Commit messages, branch and file names and tool names are escaped in the
  Git panel, tool rows and plan graph; a commit message could run script in
  the app before.
- Gate hooks that time out or can't start now block the call.
- Workers can call only the tools they were given; a read-only worker could
  start a writer before.
- A malformed `lumi-policy.json` in a repository no longer drops the
  organization's rules, and an organization policy with a mistake refuses
  model requests instead of counting as no policy.
- Plans, roadmaps and autonomous sessions follow a chat's exclusions, project
  trust, allowed modes, organization and project rules and hooks. The terminal
  UI follows `lumi run`'s rules, and your Settings hooks run in `lumi run`,
  scheduled tasks, model comparisons and the chat gateway.
- The computer use switch also covers the clipboard, screen recording and
  accessibility tools. On macOS a window title can no longer inject
  AppleScript.
- Issue links send code host tokens only to known hosts.
- A settings file Lumi can't read (one with a byte-order mark, or held open by
  another program) is no longer overwritten with defaults, and each save keeps
  `settings.json.bak` without keys.

### Agent and models

- **Anthropic and OpenAI adapters**, also for Amazon Bedrock, Google Vertex AI
  and Azure OpenAI. **Custom connections** for OpenAI-compatible endpoints and
  proxies, with **Test connection**, and sign-in to enterprise endpoints with
  OAuth client credentials, Microsoft Entra ID or client certificates.
- **Fallback models**, **Models for roles** and, through a policy, capability
  overrides per model. **Image descriptions:** with a vision model set for
  that role, a text-only model gets descriptions of attached images and
  screenshots.
- **Model providers as extensions:** a capability pack can add a provider as
  its own program (Extension SDK v1, `lumi extension check`).
- **Permission modes:** Ask asks before changes; new installations start in
  Auto-edit; Full-auto work started from another mode asks for that run.
- **Plans:** `/plan` works again, with Pause, Resume and Stop; a reloaded page
  picks up a running plan; a plan's specialists report under its card.
- **Autonomous sessions** are experimental and off by default (Settings ›
  General), with a spending limit. An iteration no longer waits until Stop,
  and a reflect pass reports under its own card.
- **Counts you can trust:** changed files count only edits that happened, a
  `!command` turn counts only its own work, worker hand-offs report only
  what happened, and model comparisons include what a run committed.
- **Code intelligence:** a `code_intel` tool gives definitions, references and
  diagnostics from a language server, in trusted projects.
- **Large repositories:** the index follows `.gitignore`, stops at 100,000
  files and is much faster.
- **Pull requests** on GitHub, GitLab, Bitbucket Cloud and Azure DevOps
  (view, check logs, create, comment and update; the ones that change
  something ask first), and **issue trackers** (Jira, Linear, GitHub and
  GitLab) with `@issue:`.
- **Compare models on your tasks** (Settings › Model evaluations), each run in
  its own worktree.
- **Usage and cost:** a record of each model call, prices from the provider or
  a bundled list (unknown models count as unpriced, not free), `lumi usage`,
  and personal limits: **Ask before spending more than ($ per day)** and
  **Stop a turn after spending ($)**.
- **A new Windows computer:** Lumi works without Git, Python or Node.js,
  decodes command output in any code page, shows search results relative to
  the project, and tells the model which tools are installed.
- **Workers** can be paused, resumed, steered, stopped and restarted, with
  their transcripts and hand-offs in the conversation.
- **From the 0.19.2 development builds:** an optional enforced limit on model
  requests; project-owned `job_start`, `job_status` and `job_cancel` for long
  foreground work such as renders; multiline Windows shell commands refused
  before they could silently run in part; SONN error messages, text-only
  screenshot handling and retries; recovery from a malformed conversation
  summary; and the AI Employee source integration, which is paused (see the
  [handoff](ai-employees-handoff.md)).

### Team (preview)

- **The Team panel:** investigations you assign, or a coordinator's plan you
  review; one to eight workers; scoped reads; writers in isolated worktrees;
  named checks; reviewed application and acceptance; pause, steer and stop;
  recovery after a restart without replaying uncertain work; follow-up plans;
  reports.
- **The orchestrator:** `/team <objective>`, one to eight rounds, answers to
  workers during a round, one retry of a failed task, and **Apply changes that
  pass every check**. Results it accepts under your grant are recorded as
  such, never as your review. **Continue** resumes it after a recovery.
- **Use in chat** attaches a team's results (`@team:<run id>`) to your next
  message.
- Workers can use a **Worker model** of their own, and can message each other
  and the orchestrator (**Team messages**).
- Under an organization policy, personal teams follow its model, mode, shell,
  budget and audit rules.
- Clean-up: writer branches are named `lumi/team-<writer>`, finished work is
  removed, and work that may not be applied stays until **Discard kept work**.
  Worktrees (a team's, an agent's, a model comparison's) are removed without
  following links, so a junction inside one can't lead to deleting files
  outside the repository.
- Steadier on a busy computer, and a team holds only its own conversation.
- Also in the source, for later: sharing between two of your conversations,
  and teams managed by an organization through a separate governance service.

### Desktop and UX

- **A new name and look:** the Lantern mark, gold on night, and dark and light

- **First run:** the terms dialog; a getting-started checklist with a sample

- **Timeline** of checkpoints: restore files, the conversation or both;

- **Trace**, **Save for OpenTelemetry** and **Saved** for each run.
- **Evidence:** each call drawn once, late results settled, failures and

- **Dictation:** hold or toggle the microphone (Ctrl+Shift+Space). It keeps

- **Accessibility:** text contrast of at least 4.5:1 in both themes, keyboard

- **Code editors:** a VS Code extension (also for Cursor, Windsurf and

- **Capability packs:** install from a public Git repository at a pinned

- **Send feedback**, **Help › About Lumi**, and a support address in the
  diagnostics ZIP's note.
- In a browser tab that shares the desktop app's server, choosing a project
  folder opens a dialog to type the path, instead of a native picker the tab
  couldn't see.

### Terminal UI, headless and command line

- `lumi run` for CI and scripts: a JSON result, exit codes 0 to 3, `--mode`,
  `--trust-project`, `--max-requests` and `--timeout`. A container image
  definition is in `packaging/docker/`.
- `lumi schedule` and **Settings › Scheduled tasks** run tasks through Task
  Scheduler, launchd or cron.
- `lumi gateway` asks for approvals in the Telegram or Slack chat and starts
  in `--mode ask`.
- The terminal UI starts in your default permission mode (`--approve` for
  Ask, the new `--full-auto`), keeps `lumi run`'s rules, prints names and text
  as written, and says why a call was refused.
- New commands: `lumi terms`, `lumi policy`, `lumi updates`, `lumi usage`,
  `lumi license`, `lumi editor` and `lumi extension`.

### Enterprise and Lumi Cloud (preview)

For organizations. Lumi Cloud, Luminary's service for organizations, isn't
hosted yet, so the features below that need it can't be used in this alpha.
Organization policy works from a policy file or Group Policy on the computer.

- **Organization policy** (`lumi.policy/v1`) from Group Policy and Intune,
  macOS configuration profiles or a policy file: locked settings, allowed
  modes and models, file exclusions, shell, MCP and pack allowlists, signed
  policies. See [Organization policy](enterprise-policy.md).
- **Audit log:** hash-chained records of turns, tool calls, approvals and
  settings changes, checked in Settings and exported over OpenTelemetry.
- **Budgets** per user, project or turn; **zero data retention**
  requirements; **data loss prevention** rules for everything sent to models.
- **Organization oversight**, off unless a policy turns it on: a notice people
  confirm before any model use, signed acknowledgments, and the activity the
  policy asks for, sent to the organization's Lumi Cloud.
- **Offline and air-gapped mode (first pass):** Lumi reaches only this
  computer and the hosts you allow; updates from a file on Windows; an offline
  license that labels offline use and locks nothing.
- **Needs Lumi Cloud:** the Lumi account and enrollment, signed policy
  delivery, sharing a conversation, hand-offs to a teammate (hand-offs to a CI
  run work without it), second-person approval of risky commands, the review
  queue for agent changes, the team library (project notes, skills and
  prompts), tasks from Slack and Teams, and shared model credit. The client
  now sends each sign-in's tokens only to the Lumi Cloud that issued them, and
  device requests only to the one the computer enrolled with.
- **Deploying:** an MSI for Intune, Configuration Manager and Group Policy
  (built for stable releases only), a macOS installer package and
  configuration profiles, and Linux packages (built in CI, not published).

### Packaging, install and updates

- **The installer** is now Lumi's (`lumi-setup-X.Y.Z.exe`, `Program
  Files\Lumi`, a new AppId). It removes SONN Client or Resonant first, and its
  license page is skipped on updates when the terms haven't changed.
- **Settings › Updates** chooses the channel (Stable or Beta), a release line
  to stay on, and whether to check automatically, only when asked, or never.
  Pre-releases reach only the beta feeds.
- **Updates wait for a running turn.**
- **The macOS app (preview):** Lumi.app in a disk image, updated by Sparkle 2
  from signed macOS feeds, signed ad hoc until an Apple Developer ID is set
  up.
- **Supply chain:** hash-pinned build dependencies, a weekly dependency audit,
  third-party notices with each component's full license text, and a
  CycloneDX SBOM with each release. Windows code signing through Azure
  Artifact Signing is wired into the release workflow and turns on once
  Luminary's signing account is set up.
- Installers and update feeds are served from Luminary's update site on
  GitHub Pages.
