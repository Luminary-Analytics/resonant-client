# Resonant Client v0.12.4

A crash fix in the computer-use indicator, and some dead code removed.

## Fixes

- **The on-screen indicator could crash the process.** Creating its window used
  an undeclared Windows call, which truncated a 64-bit handle and faulted. It
  only misbehaved when the operating system happened to load the application
  above a certain address, so it never appeared in normal use and showed up as
  an intermittent native crash rather than an error message. The remaining
  window calls are now declared explicitly and covered by a test.

  If you have been running computer use since v0.12.0 and saw an occasional
  unexplained crash, this is the likely cause.

## Changes

- **Removed `SafetyZone`.** It described a screen region where automated
  actions would be blocked, and nothing ever called it — enforcement was never
  built and, by design, is not going to be. Dead code that names a protection
  is worse than no code at all: it reads as evidence the protection exists.
  Desktop actions continue to run without prompting, unchanged.

## Validation

- Full Python suite: 3,011 passed, 2 platform-skipped. Ruff clean.
- The crash was verified gone across five consecutive runs of the test file
  that reproduced it, plus a full-suite run checked explicitly for native
  faults. Worth noting: this crash never failed a test. It happened on a
  background thread, so the suite reported everything passing while printing an
  access violation in its own output — the new test asserts the underlying
  declarations directly, because a crash of this kind cannot be caught.
- The tool-routing tests no longer create real windows on the test machine or
  in CI, which is what had been obscuring the fault.
