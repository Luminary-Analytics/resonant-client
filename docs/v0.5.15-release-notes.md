## a1: build_resume_prompt coverage

The `build_resume_prompt` method composes the system prompt for a resumed harness session. Three roles each get a distinct read-order + role-specific task block, plus seven optional sections that fire conditionally based on workspace state. Pre-v0.5.15 it was the only meaningful uncovered surface left in `harness/service.py` after v0.5.14a1's 50-test coverage push.

A regression in this method would silently degrade resumed-session prompts — agents would still run but with incomplete context, the kind of slow-burn defect that's hard to notice without a direct test.

[tests/test_harness_service_resume.py](../tests/test_harness_service_resume.py) ships 19 tests across 6 classes:

- `TestBuildResumePromptChatMode` (1) — chat mode short-circuits to the canned "Resume the chat conversation naturally..." string.
- `TestBuildResumePromptReadOrder` (2) — planner gets `spec.json` FIRST in the read order; evaluator omits spec entirely (focus is on contract + report, not product vision).
- `TestBuildResumePromptRoleBlocks` (3) — planner / generator / evaluator each get distinct task lists with role-specific phrasing + correct JSON-block expectations (`planner_update` / `generator_update` / `evaluator_verdict`).
- `TestBuildResumePromptSpecLines` (3) — planner + generator include `Product title:` + `Product summary:`, evaluator omits, fallback to `"Unknown"` / `"Not set"` when spec is empty.
- `TestBuildResumePromptConditionalSections` (8) — every optional section verified: capped at 5 entries (the populated workspace fixture seeds 6 entries each for blockers / next_steps / acceptance_checks / required_revisions; only 5 should appear), validation_checks + validation_artifacts present, acceptance_evidence truncated to 180 chars per entry, empty workspace omits ALL optional section headers.
- `TestBuildResumePromptMetadata` (2) — sprint_id + objective render correctly; fallback strings (`"none"` / `"unknown"`) fire on empty workspace (note: contract status defaults to `"proposed"`, not `"unknown"` — the `or "unknown"` fallback only fires when the value is falsy).

Coverage on `resonant_client/harness/service.py`: **69% → 100%**. Every line in the module is now exercised by combining `test_harness_service.py` (v0.5.14a1) + `test_harness_service_resume.py` (this alpha).
