# Resonant Client v0.12.0

Computer use is now a first-class, model-aware capability — and you can always
see when it is happening.

## The agent can drive your desktop, when the model can actually do it

Resonant has shipped desktop tools for a while — screenshot, click, type,
scroll, drag, hover, window focus, OCR, launch an application. Until now every
model was offered them, including models that cannot see a screen. A text-only
model handed `computer_click` can only invent coordinates: it clicks
confidently in the wrong place and reports success, which is worse than not
having the tool.

Desktop tools are now offered only to models that can genuinely use them —
those with **both** vision and reliable tool calling. Kimi K3 qualifies, as
does any vision model with native tool support; the rule is derived, not a
hand-maintained list, so a new capable model works without a Resonant update.
If a provider reports vision and tools at runtime for a model we assumed was
text-only, that report wins.

## You can see when Resonant has the mouse

While the agent is driving your machine, the screen it is working on gets a
soft purple glow around its edges and a banner reading **"Resonant is using the
computer"**. The glow pulses gently so it stays noticeable without being
distracting during a long run.

Details that matter in practice:

- **It never blocks you.** The overlay is click-through — every click goes to
  whatever is underneath it.
- **It picks the right screen.** On a multi-monitor desk the glow follows the
  monitor actually being driven, chosen from the tool's target or the click's
  coordinates, not always the primary display.
- **The agent cannot see it.** The glow is removed for the instant a screenshot
  is taken. Otherwise the model would read Resonant's own banner as part of the
  application it is looking at — and the banner sits exactly where a window
  title bar usually is.
- **It stays lit across a burst.** A run is many clicks and screenshots a few
  hundred milliseconds apart; the indicator holds through them and fades a few
  seconds after the agent stops.

It is on by default and can be turned off with the `computer_use_indicator`
setting under **general**. Windows only for now; a no-op elsewhere.

## Validation

- Full Python suite: 2,994 passed, 2 platform-skipped. Ruff clean.
- The overlay was verified on a real two-monitor desk: glow renders on the
  correct screen including one at negative coordinates, the banner is legible,
  and a screenshot taken while it is lit contains no trace of it.
- Three concurrency bugs were found and fixed during that testing — a
  cross-thread `ShowWindow` deadlock, a capture that could race a pending show,
  and a linger timer that could strand the glow on screen permanently. Each has
  a regression test or a deterministic reproduction.
