# v0.4.x — DeepSeek harness roadmap

This is the working backlog of deepseek-specific optimizations for the post-v0.4.0 era. Each item is sized to fit in a focused commit and is self-contained enough that an autonomous loop can pick the next unchecked item, execute it, ship it, and move on.

**For autonomous-loop runs:**
1. Read this file top to bottom.
2. Pick the first unchecked `[ ]` item that's not blocked.
3. Execute it (implement + test + commit + push).
4. Mark it `[x]` with the version it shipped in.
5. Stop and report if you hit anything ambiguous or that needs a real human decision.
6. Otherwise, move to the next unchecked item.

**Constraints for autonomous work** (don't violate without explicit user approval):
- No real-API mission runs (cost money, can hang). Use unit tests + Chrome MCP smoke tests against the dev server.
- No big architectural changes without checking in. Subtractive cleanup, additive features with tests, prompt tuning — all OK.
- No public-API breakage. The cycle-guard / `await_user` / `working_subdir` mechanisms are now load-bearing.
- Each commit ships independently — pytest must pass before commit.
- One feature per commit, per release. No mega-PRs.

## Tier 1 — Table stakes the v0.4.0 cut exposes

- [x] **T1.1 — Mac Studio default URL is the FIRST probe target.** Shipped v0.4.1. New `tests/test_network_defaults.py` (14 tests) pins the resolution chain: explicit > `OLLAMA_HOST` env > `network.ollama_url` setting > Mac Studio default `http://10.0.0.133:11434`. Includes a defensive `test_does_not_silently_fall_back_to_localhost` that asserts the URL never contains `localhost` or `127.0.0.1` on a fresh install — catches future regressions where someone might add a "fall back to localhost" patch.

- [x] **T1.2 — Localhost fallback as a wizard option.** Shipped v0.4.2. Added a quick-fill chip row under the URL input with two chips: `Mac Studio` (`http://10.0.0.133:11434`) and `localhost` (`http://localhost:11434`). Clicking a chip pre-fills the URL field AND immediately re-probes via the existing `update_settings` + `redetect_backends` flow — one click gets dev-only users unstuck. Refactored the existing Test handler to share a `probeUrl` closure so the chips and the Test button take the same path.

- [x] **T1.3 — Connection probe response feedback in the wizard.** Shipped v0.4.3. Backend now emits `ollama_probe_result` event (`{ok, url, models_count}`) BEFORE the init payload on `redetect_backends`. Wizard renders three states: "Probing… <spinner>" while in flight, "✓ Reachable at URL — found N models" / "✓ Reachable, no models pulled yet" / "✗ URL unreachable" on result. 7s client-side safety timeout catches the case where the backend never emits (network stack hung). Generation token prevents stale events from a fast-double-click overwriting fresher results. New `.ollama-wizard-hint-ok` style + 8px brand-colored spinner.

- [ ] **T1.4 — Retire the `lmstudio_url`, `resonant_api_url`, `remote_engine_ws_url` fields from settings.py once we're sure no migration path needs them.** v0.4.0 left them in for safety; remove in v0.4.1 with a warning when they're set.

- [ ] **T1.5 — Remove dead resonant-cycle WS handlers in `gui/app.py`.** The `start_harness_cycle`, `list_harness_cycles`, `get_harness_cycle`, `cancel_harness_cycle`, `recover_harness`, `set_harness_sprint`, `set_harness_contract_status`, `set_evaluator_verdict`, `apply_harness_update` paths all guard with `getattr(state.backend, "name", "") == "resonant"`. With ResonantBackend gone, these branches never fire. Delete them.

## Tier 2 — Model-specific tuning

- [ ] **T2.1 — Per-tier context budget.** `deepseek-v4-flash:cloud` and `deepseek-v4-pro:cloud` have different effective context windows. Add a `_model_context_budget(model_name)` helper in `engine/compression.py` that returns the right `should_compress` threshold per model.

- [ ] **T2.2 — DeepSeek tool-call format quirk audit.** Ollama's tool-call format is mostly OpenAI-compatible but DeepSeek may emit unusual `arguments` JSON escaping (especially with embedded newlines or quotes in `bash` commands). Write `tests/test_deepseek_tool_format.py` that synthesizes a few known edge cases and verifies our parser handles them.

- [ ] **T2.3 — Specialist prompt tuning for deepseek.** The implement / explore / plan / verify system blocks were written generically. Tune the phrasing for what flash/pro respond well to. Specifically: flash sometimes skips the `## Final spec` JSON envelope unless heavily reinforced (saw this in cross-model testing). Add a "FORMAT REMINDER" block.

- [ ] **T2.4 — Per-model cycle-guard threshold.** Flash burns tokens fast; pro is more deliberate. Maybe `CYCLE_WINDOW_REPEAT` should be 4 for pro instead of 3. Add a `cycle_window_repeat_for_model(model)` helper in `engine/session.py` and use it where the constant is currently used.

- [ ] **T2.5 — `await_user` discoverability in specialist prompts.** The tool exists; specialists rarely call it. Add to the implement/explore/plan prompts: "If you've made 5+ tool calls without converging, prefer calling `await_user` with a focused question over more searching."

- [ ] **T2.6 — Cycle-guard → await_user nudge.** When the *windowed* cycle guard would trip, instead of immediately aborting, inject a one-shot system message: "You're cycling — call `await_user` with a focused question, or summarize what you have so far." Gives the agent one chance to recover.

## Tier 3 — Harness as a product

- [ ] **T3.1 — DeepSeek-specific eval harness.** Build a small repeatable test set in `tests/evals/` ("scaffold this thing", "fix this bug", "refactor this file") that runs against flash + pro and reports pass/fail + cost/latency. Output is a CI artifact. Don't run on every PR — gated to `tests/evals/` with `--evals` flag.

- [ ] **T3.2 — Mac Studio model warmup.** When `detect_backends` finds Ollama at the Mac Studio URL, opportunistically warm up the configured default model in the background (`/api/generate` with empty prompt). The first user message will then stream immediately.

- [ ] **T3.3 — Local-vs-cloud variant switcher.** If the user has both `deepseek-v4-flash:cloud` and a local quantized deepseek pulled, expose the choice with cost / latency hints. Probably a small subtitle in the model picker.

- [ ] **T3.4 — Ollama health monitor in the chat header.** Tiny dot indicator (green/yellow/red) showing Ollama reachability; tooltip shows last successful probe time + URL. Polls every 30s.
