## a1: hook factory

The v0.6.0 GA shipped the hook plumbing in `DaemonHooks` (the `extract_skill_hook` + `queue_curation_hook` fields). v0.6.1a1 connects them to actual implementations inside `build_autonomous_mission_hooks` so production daemons get the loop firing automatically — not just tests.

`build_autonomous_mission_hooks` gains two flags (default `True`):
- `enable_skill_extraction`
- `enable_skill_curator`

When enabled:
- `extract_skill_hook` wraps `extract_skill_from_iter` and runs it in a daemon thread (so a slow model session doesn't pin the iter loop). Bad kwargs (signature drift) are logged + skipped, not raised.
- `queue_curation_hook` checks the rate limit upfront (cheap path — no thread spawn when the curator just ran in the last 24h), then spawns a daemon thread for the actual curation pass.

Both hooks use module attribute access (`sme.extract_skill_from_iter`) rather than closure-captured imports so test patches via `unittest.mock.patch("...skill_mission_extraction.extract_skill_from_iter", ...)` actually take effect. Production behavior is identical either way; just keeps the test surface honest.

## a2: `resonant-skill` CLI

A new console script (`resonant-skill`) registered alongside `resonant`, `resonant-tui`, `resonant-gui`, `resonant-smoke`. Mirrors the `resonant-smoke` pattern with module-local `cli.py`.

Subcommands:
- `list` — enumerate skills with `--scope` / `--created-by` / `--pinned` / `--include-deprecated` / `--json` filters.
- `view <id>` — print skill metadata + `procedure.md` body, or full `skill.json` with `--json`.
- `pin / unpin <id>` — toggle pinned flag (curator-exempt durability).
- `archive <id>` — manual archival; refuses bundled / user / pinned with exit 2.
- `curate [project_path]` — run a curator pass NOW (skips rate limit). Supports `--dry-run`.

**Two issues caught during dogfood smoke testing:**

1. Bundled skills don't auto-install on first CLI run. They ship in the package via `importlib.resources` but only materialize via `install_bundled_skills()` — currently called nowhere in the boot path. **Fixed in a3.**
2. Windows cp1252 console can't print 📌 / → / em-dashes. Fixed via `sys.stdout.reconfigure(encoding="utf-8", errors="replace")` at CLI entry. Falls back gracefully on terminals that can't render the glyph (gets `?` instead of a crash). Also swapped 📌 to `[PIN]` in CLI list rows because the marker shows in every row regardless of skill description; cleaner ASCII for default.

Live CLI verified:
```
$ python -m resonant_client.orchestration.skill_cli list --created-by bundled
Found 2 skill(s):

[PIN] [bundled] autonomous-mission-iter-discipline    (global)   Conventions every autonomous mission iter follows. Codified from v0.5.6 → v0.5...
[PIN] [bundled] rigorous-grill-spec-refinement        (global)   5-beat question pattern that consistently produces dispatchable specs...
```

## a3: promote/demote + auto-install

Three things ship together:

1. **`promote_skill(skill_id, *, project_path, keep_project_copy=False)`** — elevates a project-scoped skill to global scope. Refuses bundled (already global, can't elevate). Refuses on global-collision (user resolves manually). Preserves provenance, pinned flag, success/fail counts, `procedure.md` + `verification.md` sidecars. Default archives the project copy via `deprecate_skill`; `--keep` leaves both in place.

2. **`demote_skill(skill_id, *, target_project_path, keep_global_copy=False)`** — the inverse direction. Same collision + bundled refusal rules. Useful when a skill turns out project-specific and was elevated by mistake.

3. **CLI auto-installs bundled skills at every invocation.** Idempotent (skips skills already on disk), cheap (one stat per bundled skill), guarded by try/except so a broken bundled skill doesn't block CLI use. Means `resonant-skill list --created-by bundled` now shows the reference skills out of the box without a manual install step — answers the v0.6.1a2 followup directly.

CLI subcommands added:
- `resonant-skill promote <id> --project-path <p> [--keep]`
- `resonant-skill demote <id> --project-path <p> [--keep]`

Both return exit 2 on refusal (bundled / collision / missing) with diagnostic stderr output covering the three failure modes.

## What this delivers

After v0.6.0 GA, the loop existed in code but the production hooks weren't actually wired. After v0.6.1, an autonomous mission daemon constructed via `build_autonomous_mission_hooks` will:

1. Fire the **extractor** in a background thread on every successful iter (verdict=satisfied, not overridden) — the model decides whether the iter produced a reusable pattern + writes the skill if so.
2. Queue the **curator** in a background thread when the mission terminates with `reason=satisfied` — rate-limited to once per 24h per project, archives stale agent-created skills.

Plus the user has a **CLI surface** to inspect, pin, archive, and elevate skills outside the autonomous flow. The day-to-day commands round out the lifecycle.

- **Model-driven curator** (umbrella consolidation): forked agent merges narrow sibling skills into broader umbrellas. Spec exists in PLAN-SELF-IMPROVEMENT.md; deferred from v0.6.0; still deferred. Worth shipping when the user has accumulated enough agent-created skills to stress-test the consolidation.
- **Embedding-based matching** (currently keyword Jaccard): a v0.7-class change that adds a sentence-transformer dep.
- **GUI surface for skills**: the v0.6.x line is CLI-only. A skill panel in the GUI (alongside the existing mission browser) would let users see what skills are surfacing in their current mission's context.
- **Field-run validation**: P0 carry-over from v0.5.x. Dispatch mdcheck WITH v0.6.1 enabled, run two missions in the same project, verify the second mission references skills the first produced.
