## a1: per-specialist Ollama model routing

The linux-bridge run hit `verdict=stuck` on a path-mismatch that arguably needs stronger reasoning. Rather than re-introduce Anthropic/OpenAI backends (cut in v0.4.0 to be Ollama-native), v0.5.8a1 lets you pin a stronger Ollama model per specialist. Pro for the high-leverage decide moments (REFLECT, PLAN_DEEP), flash for the bulk (IMPLEMENT, EXPLORE). Local-first stays intact.

**Architecture:**

1. `LocalSpecialistRunner.specialist_backend_resolver` — optional callable mapping `NodeSpecialization` value to a backend instance. Returns None to fall through to the runner's default backend. Resolver exceptions are caught + logged; routing failures never block a specialist from running.

2. `IntentService` and `make_reflect_runner` thread the resolver through. Backwards-compat — services constructed without it behave exactly as before.

3. `AppState._resolve_specialist_model_override(specialization)` reads from `general.specialist_model_overrides` (settings.json) first, falls back to `RESONANT_SPECIALIST_<NAME>_MODEL` env var. `_build_specialist_backend` constructs a fresh `OllamaBackend` with the override model, inheriting `base_url` + `thinking_mode` from the active default backend so only the *model* changes.

**Settings shape:**

```json
"general": {
  "specialist_model_overrides": {
    "reflect": "deepseek-v4-pro:cloud",
    "plan_deep": "deepseek-v4-pro:cloud"
  }
}
```

**Env override (for power users):**

```
RESONANT_SPECIALIST_REFLECT_MODEL=deepseek-v4-pro:cloud
RESONANT_SPECIALIST_PLAN_DEEP_MODEL=deepseek-v4-pro:cloud
```

Settings wins over env so persistent UI configuration is authoritative. Both empty → default backend.

**24 new tests** covering runner resolver dispatch (no resolver / None / override / raises), end-to-end Session-uses-resolved-backend, settings + env resolution priority, malformed/missing/non-string values, OllamaBackend constructor failure tolerance, IntentService wiring.

## a2: human-in-the-loop on stuck verdict

Closes linux-bridge field-observation #10. Before this, when REFLECT hit a fork it couldn't autonomously resolve (canonical case: `[bash]` criterion with wrong path, e.g. `recipes/` vs `src-tauri/recipes/`, where the file IS present at a different location), it had two unappealing options: declare `verdict=blocked` and the daemon would go stuck, or flip the criterion to FAIL without acting. Linux-bridge took the former on iter 12.

**Fix: structured park-and-resume cycle.**

REFLECT-side:
- New optional `decision_request` field in the JSON verdict envelope.
- New "HUMAN-DECISION-REQUIRED" section in the REFLECT system block with rules: only when truly ambiguous, ≥2 distinct options, do NOT re-emit the same request after a user has answered.
- `validate_decision_request()` defensively cleans up the payload (filters bad options, deduplicates ids, requires ≥1 option with both id and label).

Daemon-side:
- New `provide_decision(option_id, response_text)` thread-safe public method.
- `_run_full_reflect` parks (NOT terminal) when outcome carries a well-formed `decision_request`: emits `autonomous_human_decision_required`, blocks on `_wait_for_decision()` (with stop_event check so user_stop wins), emits `autonomous_human_decision_received`, then re-runs REFLECT with the user's choice folded into the prompt as `## User decision (act on this)`.
- `stop()` sets `_decision_event` so a parked daemon unwinds cleanly.

WS-handler:
- New `autonomous_mission_decision` command takes `intent_id`, `option_id`, optional `response_text`. Routes via `provide_decision()`, echoes `autonomous_decision_dispatched` so the GUI knows the round-trip landed.

Frontend:
- `handleAutonomousHumanDecisionRequired` renders an inline yellow card with question, radio-button options, optional notes textarea, Submit button.
- `handleAutonomousHumanDecisionReceived` converts the active card into a one-line "Decision applied" green chip.

Hook signature is now `run_full_reflect(roadmap, pass_result, decision_context="")`. Old 2-arg hooks fall through gracefully via `TypeError` catch (the user's choice is still recorded in the event log, just not folded into the prompt).

**17 new tests** covering the validator, the verdict parser, end-to-end park-then-resume with the kwarg threaded through, stop-during-park unwind, no-op when not parked, old-2arg-hook fallback.

## a3: chat virtualization via iter folding

Closes linux-bridge field-observation #7. After ~2h of accumulated chat content (388 messages), Chrome's `Page.captureScreenshot` was timing out — DOM had grown too large for layout/paint.

**Fix: native `<details>` folding of older iter blocks.**

When a new iter starts and there are 3+ iters in history, the oldest gets wrapped into a one-line collapsible affordance. The DOM stays the same size in element count, but the BROWSER doesn't lay out or paint hidden content — which is exactly what was timing out.

- `_renderIterationCard` calls `_foldOlderIterationsIfNeeded(N)` after each new iter card.
- The fold keeps the 2 most recent completed iters + the live one expanded; everything older folds. Tunable via `KEEP_RECENT`.
- `_foldSingleIterBlock` walks siblings forward from the iter card to the next iter card boundary, wraps them in `<details>` with a one-line summary (iter number, item id, status: shipped/failed/in flight, duration).
- Native `<details>` is the right primitive — keyboard-accessible, no JS state to manage, browser handles toggle.
- Idempotent via `data-folded` flag.

Click a folded iter's summary to expand it back. Status badge picks up the right color (green for shipped, red for failed).

Frontend-only.

## a4: smoke spec library expansion

Closes P5. Two new specs + a `seed_files` mechanism for refactor-style specs.

**Both new specs are CURRENTLY UNVALIDATED** — added with hand-estimated `expected_iter_seconds` ranges; need a live Mac Studio run to pin convergence numbers. The CLI surfaces this via a `[unvalidated]` marker in `list-specs` output.

**New specs:**

1. **jsonlines** — single-file Python CLI that converts JSONL to CSV given a column list. 5 bash criteria including I/O equality on a fixture with missing-key handling. Different I/O shape than wordcount (JSON parsing, columnar output) at similar scope.

2. **refactor-py** — the first non-greenfield spec. Pre-seeds `fizzbuzz.py` with an intentional off-by-one bug + a `tests/test_fizzbuzz.py` that catches it. Agent's job is to fix the bug without touching the tests. 5 bash criteria including a `git diff --name-only -- tests/` guard against model attempts to "fix" failures by editing tests.

**New mechanism:**

`SmokeSpec.seed_files: dict[str, str]` — maps repo-relative paths to verbatim file contents. The smoke runner writes these to the fresh project + commits them BEFORE dispatching the autonomous mission, so the agent sees them as pre-existing project state. Empty for greenfield specs.

`make_fresh_project(prefix, seed_files=None)` writes seeds, runs `git add -A && git commit`, lands as a second commit (after the empty initial).

`SmokeSpec.validated: bool` — defaults to True for the v0.5.x staples (validated in v0.5.0/v0.5.2 smokes). New specs ship with `validated=False`. CLI prefixes `[unvalidated]` and shows a footer note.

**19 new tests** covering registration, parse/criteria sanity, validated flag, seed_files default+population, `make_fresh_project` seed-write+commit behavior, refactor-py seed sanity (the bug actually fails the seeded test, the test file pins the function signature, etc.).
