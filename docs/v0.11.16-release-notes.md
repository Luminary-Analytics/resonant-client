# Resonant Client v0.11.16

Fixes for the first real session with native browsing.

## Fixes

- **A run no longer breaks when the agent stops to ask you something
  mid-tool-call.** If the agent started a tool, paused for a question, and you
  answered, your reply landed between the tool call and its result — and the
  provider rejects that with `an assistant message with 'tool_calls' must be
  followed by tool messages responding to each 'tool_call_id'`. Because the
  conversation is replayed on every request, the session then failed the same
  way forever; Retry and Continue could not help. Results are now kept next to
  the call that produced them.

- **"Ollama is not reachable" when Ollama is running.** Provider detection is a
  single probe with a two-second connection timeout, and its result was cached
  for the whole session. One slow response at startup — routine when Ollama is
  on another machine — meant Resonant insisted it was down until you restarted.
  It now re-checks before making that claim, and the message names the URL it
  actually tried instead of quoting the default.

- **The "tool server unavailable" notice can be dismissed.** It now has a close
  button. Dismissing is remembered for that specific message, so it stays gone
  without hiding a different problem later.

## Changes

- **BrowserOS has been removed.** It was the default browser MCP server back
  when browsing needed one. Browsing has been built in since v0.11.15, so the
  entry did nothing except report itself as an unavailable tool server. It is
  removed from existing installs too, not just new ones — a customised entry
  (one whose URL you changed) is left alone, and you can add any MCP server
  back from **Settings > MCP Servers**.

## Validation

- Full Python suite: 2,975 passed, 2 platform-skipped. Ruff clean.
- The tool-call ordering fix is covered for the interrupted case, results
  arriving out of order, genuinely missing results, reused call ids across
  turns, and a result recorded before its call. Healthy conversations are left
  byte-for-byte unchanged.
- Dismissal verified in a running browser: the notice closes, stays closed for
  the same message, and reappears for a different one.
