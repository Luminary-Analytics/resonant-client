# v0.4.0 — the Ollama-only cut

This document describes the v0.4.0 strategic refactor for future humans and LLMs working in this codebase. If you find a backend module mentioned in older code/docs but not present in the source tree, this is why.

## What changed

Resonant Client v0.4.0 was cut to a single backend: **Ollama**. Everything else was removed.

**Removed backend classes** (formerly in `resonant_client/backends.py`):
- `ResonantBackend` — Resonant Cognitive Engine remote SSE backend
- `ClaudeBackend` — Anthropic API via the `anthropic` SDK
- `OpenAIBackend` — OpenAI API via the `openai` SDK (also handled LM Studio)
- `ClaudeCodeBackend` — wrapper around the `claude` CLI
- `CodexBackend` — wrapper around the `codex` CLI
- `MLXBackend` — Apple Silicon MLX local-runtime backend
- `_find_cli` helper — only used by the CLI-wrapper backends

**Removed dependencies** (formerly in `pyproject.toml`):
- `[claude]` extras → dropped `anthropic>=0.40.0`
- `[openai]` extras → dropped `openai>=1.50.0`
- Both lines also removed from the `[all]` extras group

**Removed Python references** (now ollama-only):
- `gui/app.py` — `detect_backends`, `select_harness_backend`, `select_harness_retry_backend`, `select_harness_teacher`, `build_backend_spec` all collapsed to ollama-only paths.
- `gui/runtime.py` — `BackendSpec.create_backend` rejects non-ollama backends with a friendly error pointing at the right upstream tool.
- `tui.py` — `_detect_backends` simplified; `/model` slash-command isinstance dispatches reduced to OllamaBackend only.
- `engine/server.py` — imports pruned.

**Removed UI**:
- Settings → API Keys section (no Anthropic / OpenAI keys to store).
- Settings → Local Backends → LM Studio URL field.
- Multi-backend grouping in the welcome-screen `showBackendSelector`. Replaced with a flat model picker for Ollama with deepseek flagship variants pinned to the top.
- The codex / claude-code recommendations in the mission composer's model hints. Replaced with deepseek tier guidance.
- The model-selector dropdown's optgroup-based "Local / Subscriptions / APIs" categorization. Single Ollama group now.
- Settings → General → Default backend select dropdown collapsed from 8 options to "Ollama / Auto".

**Added UI**:
- **Welcome-screen Ollama setup wizard** (`_renderOllamaSetupWizard`) — shown when `backends.ollama` is absent or empty. Three steps: URL field with test button (default Mac Studio at `10.0.0.133:11434`), install link to ollama.com, `ollama pull deepseek-v4-flash:cloud` hint. URL update flows through `redetect_backends` so the user never has to leave the window.
- **`network.ollama_url`** field in Settings → Network. Backed by the new `resolve_ollama_url` chain in `network_defaults.py`.

## Why

Anthropic and OpenAI both ship excellent first-party agentic coders for their own models — Claude Code, Codex. Nothing matches that integration if you're already in their ecosystem. There's no equivalent purpose-built tool for the **open-source local model** path, particularly DeepSeek's V4 family running through Ollama. Resonant Client v0.4.0 is that tool.

The product surface is now shaped by the single trust path:
- Every feature (Mission flow, cycle guards, await_user, working_subdir propagation, diagnostics ZIP) is exercised by every user.
- Tuning is concrete — there's one model family to optimize for instead of 6.
- The Tier-1 mission test surfaced a real concern with the multi-backend story: v0.3.5's `await_user` tool wasn't available with claude-code (claude-code uses its own native tools, bypassing our engine dispatch). Cutting claude-code makes the engine-path features apply to every user.

## How the cut was done (for future similar refactors)

1. **Mapped the surface** before editing — used the Explore agent to find every reference to the cut backends with file:line refs (~13 files, ~1,700 lines).
2. **Truncated `backends.py` at the OllamaBackend boundary** (line 927) and appended a new `create_backend` factory that explicitly rejects non-ollama backends with a friendly error message.
3. **Pruned imports** in `app.py`, `runtime.py`, `tui.py`, `engine/server.py`.
4. **Rewrote each multi-backend selection function** to ollama-only, preserving the function signatures and env-override surface so older settings.json files load without a migration step.
5. **Simplified the JS model selector** by collapsing `_getModelGroups` and `_getPreferredBackendSelection` to ollama-only.
6. **Built the Ollama setup wizard** for the new "first-run with no backend" path.
7. **Updated tests** — `test_gui_hardening` parametrization collapsed from 6 cases to 1.
8. **Updated README** with the new positioning + Ollama-first install instructions.

## Backwards-compatibility surface preserved

- `~/.resonant/settings.json` schema — `api_keys` still loads as `{}`, old `anthropic` / `openai` keys are silently ignored. Old `default_backend = "claude"` etc. selections are tolerated by the safe-default chain (the model selector falls back to the first available Ollama model).
- `BackendSpec` JSONs — old backend types fail with the friendly error, the user gets the welcome-screen wizard.
- v0.3.5 remains downloadable on the GitHub Releases page if users need the multi-backend behavior.
