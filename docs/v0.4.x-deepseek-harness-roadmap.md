# v0.4.x — DeepSeek harness roadmap

This is the working backlog of deepseek-specific optimizations for the post-v0.4.0 era. Each item is sized to fit in a focused commit and is self-contained enough that an autonomous loop can pick the next unchecked item, execute it, ship it, and move on.

**For autonomous-loop runs:**
1. Read this file top to bottom.
2. Pick the first unchecked `[ ]` item that's not blocked.
3. Execute it (implement + test + commit + push).
4. Mark it `[x]` with the version it shipped in.
5. Stop and report if you hit anything ambiguous or that needs a real human decision.
6. Otherwise, move to the next unchecked item.

**Constraints for autonomous work** (don't violate without explicit user approval):
- No real-API mission runs (cost money, can hang). Use unit tests + Chrome MCP smoke tests against the dev server.
- No big architectural changes without checking in. Subtractive cleanup, additive features with tests, prompt tuning — all OK.
- No public-API breakage. The cycle-guard / `await_user` / `working_subdir` mechanisms are now load-bearing.
- Each commit ships independently — pytest must pass before commit.
- One feature per commit, per release. No mega-PRs.

## Tier 1 — Table stakes the v0.4.0 cut exposes

- [x] **T1.1 — Mac Studio default URL is the FIRST probe target.** Shipped v0.4.1. New `tests/test_network_defaults.py` (14 tests) pins the resolution chain: explicit > `OLLAMA_HOST` env > `network.ollama_url` setting > Mac Studio default `http://10.0.0.133:11434`. Includes a defensive `test_does_not_silently_fall_back_to_localhost` that asserts the URL never contains `localhost` or `127.0.0.1` on a fresh install — catches future regressions where someone might add a "fall back to localhost" patch.

- [x] **T1.2 — Localhost fallback as a wizard option.** Shipped v0.4.2. Added a quick-fill chip row under the URL input with two chips: `Mac Studio` (`http://10.0.0.133:11434`) and `localhost` (`http://localhost:11434`). Clicking a chip pre-fills the URL field AND immediately re-probes via the existing `update_settings` + `redetect_backends` flow — one click gets dev-only users unstuck. Refactored the existing Test handler to share a `probeUrl` closure so the chips and the Test button take the same path.

- [x] **T1.3 — Connection probe response feedback in the wizard.** Shipped v0.4.3. Backend now emits `ollama_probe_result` event (`{ok, url, models_count}`) BEFORE the init payload on `redetect_backends`. Wizard renders three states: "Probing… <spinner>" while in flight, "✓ Reachable at URL — found N models" / "✓ Reachable, no models pulled yet" / "✗ URL unreachable" on result. 7s client-side safety timeout catches the case where the backend never emits (network stack hung). Generation token prevents stale events from a fast-double-click overwriting fresher results. New `.ollama-wizard-hint-ok` style + 8px brand-colored spinner.

- [x] **T1.4 — Retire deprecated network fields.** Shipped v0.4.4. Removed `resonant_api_url` and `remote_engine_ws_url` defaults from `settings.py`. Deleted `resolve_resonant_api_url` + `resolve_remote_engine_ws_url` helpers from `network_defaults.py`. Dropped `self.api_url` + `self.lmstudio_url` from `AppState` (set but never read). Pruned the corresponding tui.py CLI flags (`--api`, `--lmstudio-url`) and the `connect` subcommand (which tunneled to the now-cut Resonant Engine WS). The "warning when they're set" approach was skipped — Python dict tolerance silently ignores unknown settings.json keys, so old configs load without crashing or noise. Deferred future cleanup: drop the unused `_detect_backends(api_url, ollama_url, lmstudio_url)` signature args + `run_remote` in tui.py.

- [x] **T1.5 — Delete dead resonant harness branches.** Shipped v0.4.5. All 9 `getattr(state.backend, "name", "") == "resonant"` guards in `gui/app.py` removed; the local `state.harness_orchestrator` / `state.harness` / `state.run_harness_teacher_escalation` / `state.apply_harness_update` paths are now the only execution path. Touched handlers: `harness_cycle_start`, `harness_cycle_list`, `harness_cycle_result`, `harness_cycle_cancel`, `harness_teacher_recover`, `set_harness_sprint`, `set_harness_contract_status`, `set_evaluator_verdict`, plus the inline `pending_harness_payload` branch in `_run_session_streaming`. ~80 lines deleted.

## Tier 2 — Model-specific tuning

- [x] **T2.1 — Per-tier context budget.** Shipped v0.4.6. New `model_context_budget(model_name)` helper in `engine/compression.py` returns per-tier thresholds: flash 24K, mid-tier 48K, pro 96K, default 100K (unchanged). `should_compress` and `compress` accept a `model_name=...` kwarg that overrides explicit `max_tokens` so callers can pass `model_name=self.backend.model` directly. Family-fallback heuristic — unknown variants like `deepseek-v5-flash:cloud` route to the flash tier via substring match. Session.run wired to pass the active backend's model name. 16 new tests in `test_compression_budget.py` covering exact match, family fallback, edge cases (None/empty), and the override semantics.

- [x] **T2.2 — DeepSeek tool-call format quirk audit.** Shipped v0.4.7. New `tests/test_deepseek_tool_format.py` (16 tests, all passing on the existing parser) synthesizes the realistic DeepSeek-shaped quirks: literal newlines / tabs / CRLF inside bash command strings, properly-escaped and unescaped Windows backslash paths, surrounding text before/after/between tool calls, triple-backtick fences wrapping the tool call, unclosed `<tool_call>` tags (GLM-4 / truncated streams), `<think>` block stripping, nested objects / arrays / unicode in args. Audit outcome: the existing 4-stage `_try_parse_tool_json` recovery (plain → escape backslashes → escape literal newlines → manual extraction) handles every case. Test file is now the spec — any parser refactor that breaks DeepSeek output will fail loudly. No source changes needed in this release; future DeepSeek-V5/V6 quirks should add cases here first.

- [x] **T2.3 — Specialist prompt tuning for deepseek.** Shipped v0.4.8. (a) Plan specialist prompt gained a FORMAT REMINDER block at the END (DeepSeek attends to recent tokens) reinforcing the JSON envelope and explicitly forbidding the common drift modes (trailing commas, single quotes, comments inside JSON). (b) Verify specialist prompt got the JSON envelope it was MISSING entirely — pre-T2.3 it just said "report a concrete verdict" in prose and relied on the runner's heuristic prose-fallback parser. Added explicit `{"verdict": "pass|revise|blocked", "findings": [...]}` schema with the same FORMAT REMINDER pattern. 9 new pinning tests in `test_specialists.py` covering the FORMAT REMINDER presence, end-of-prompt placement (>50% mark), drift-mode-forbidden language, and the verify-still-cant-edit invariant.

- [x] **T2.4 — Per-model cycle-guard threshold.** Shipped v0.4.9. Two new helpers in `engine/session.py`: `cycle_window_repeat_for_model(model)` (default 3, pro 4) and `churn_limit_for_model(model)` (default 14, pro 20). Same exact-then-family-fallback matching strategy as the v0.4.6 context-budget helper. Session.run wired to read `self.backend.model` and use the per-model thresholds. 14 new tests in `test_doom_loop.py` covering: defaults when no model, flash-keeps-default, pro-gets-bumped, case-insensitivity, family fallback for future variants, sanity bounds (cycle never exceeds half the window; churn never exceeds 30).

- [x] **T2.5 — `await_user` discoverability in specialist prompts.** Shipped v0.4.10. New "ESCAPE HATCH" block added to explore / implement / plan prompts. Each block: (a) names the tool, (b) gives a quantitative trigger ("5+ tool calls", "real ambiguity"), (c) shows 2-3 GOOD vs 2 BAD use examples specific to the role, (d) cites the cycle-guard hard-stop as a "this will happen anyway, ask first" backstop. Plan-specialist version inserts BEFORE the FORMAT REMINDER (so the JSON envelope reminder stays last). Verify deliberately omitted — its escape mechanism is the `blocked` verdict, not await_user. 10 new pinning tests covering presence per role, good/bad examples, the "user cares vs code will tell you" distinction (implement), the "before decomposing" guidance (plan), and the ordering invariant (escape-hatch before format-reminder in plan).

- [x] **T2.6 — Cycle-guard → await_user nudge.** Shipped v0.4.11. Refactored windowed cycle guard from immediate-hard-stop to two-stage (mirrors the doom-loop NUDGE_AT/THRESHOLD pattern). Pre-T2.6: hit threshold → ERROR + break. Post-T2.6: hit threshold-1 → inject one-shot "you're cycling, call await_user with a focused question, OR this will be hard-stopped on next repeat" nudge. Hard-stop now gated on `_windowed_cycle_nudged=True` (the ignored-the-nudge case). Hard-stop message updated to reference the prior nudge ("despite a prior nudge to call await_user"). Doom-loop nudge wins if both fire same turn (no message stacking). 5 new tests in `test_doom_loop.py` with a `_VaryingArgsBackend` that alternates two args (strict trailing stays at 1, but a single signature accumulates 3+ within the window — exactly the pattern the windowed nudge is for).
