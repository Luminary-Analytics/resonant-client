## a1: field run + findings

Drove the GUI through preview_* MCP tools against the Mac Studio Ollama backend at `10.0.0.133`. Two missions dispatched:

1. **Marker-append (`c39d5a57`)**: agent recognized the prompt as a "concrete instruction, not a feature" — fired the `rigorous-grill-spec-refinement` bundled skill correctly. Edit + Bash + Python all executed; the file modification + verification both succeeded. **But the mission never transitioned out of "drafting"** — it self-executed during the grill phase. The autonomous-iter loop never started, so the v0.6.0/v0.6.1 extractor + curator hooks never fired. **Zero skills captured from a successful run.**

2. **Count subcommand (real feature)**: dispatched, but `deepseek-v4-flash:cloud` was 503-rate-limited by Ollama Cloud throughout the run. Backend retry logic (1.5s / 3s / 6s exponential backoff) mostly worked, but at attempt 4/4 the iter would stall with no chat output. Banner appeared briefly then disappeared.

Captured in [`docs/field-observations/2026-05-06-v0.6.1-self-improvement-loop.md`](field-observations/2026-05-06-v0.6.1-self-improvement-loop.md). Five findings (F1-F5) ranked by severity. F1 + F2 deferred (need autonomous_loop + GUI surface changes); F3-F5 ship in v0.6.2a2-a5.

## a2: skill name generator

The field run surfaced existing skill names like:
- `actually-create-wordcountpy-with-word-counting-logic-the-fil`
- `bootstrap-a-typescript-roguelite-skeleton-with-strict-tsc-a`

Mid-word truncation + redundant verb-article prefixes that clump similar skills under the same alphabetical head. Naive `slugify(intent)[:60]` was the cause.

`slugify()` overhaul in `orchestration/skill_extraction.py`:
- Default `max_len` 60 → 30 (single eye-scan width)
- Word-boundary trunc: cut at the last `-` ≤ max_len, never mid-word
- Drop common verb-article noise prefixes (`actually-`, `create-a-`, `build-a-`, `add-a-`, `bootstrap-a-`, `setup-a-`, `make-a-`, `implement-a-`, `write-a-`, `set-up-a-` plus their `-an-` variants)
- Single-pass strip — won't recursively eat genuine signal
- Bare prefix-only slug ("create-a") collapses to `"skill"` fallback
- `drop_prefixes=False` opt-out for callers that want raw

Both call sites (`skill_extraction::_derive_skill_id` and `skill_mission_extraction::_build_skill_from_extraction`) benefit automatically — neither overrode the default before.

38 tests in [tests/test_skill_naming.py](../tests/test_skill_naming.py).

## a3: GUI skill surface

Skills had no UI presence — users had to drop to the `resonant-skill` CLI to inspect anything. v0.6.2a3 adds a Skills group in the sidebar (below Missions) and a detail modal accessible by clicking any row.

**Backend** (`gui/app.py`): four WS commands — `skill_list`, `skill_view`, `skill_pin_toggle`, `skill_archive`. Two payload helpers (`_skill_list_payload`, `_skill_view_payload`) project skills to JSON-safe rows + include `procedure_md` body in the view payload so the modal renders without a second round-trip. Refusal rules mirror the CLI: bundled / user / pinned skills can't be archived.

**Frontend** (`static/app.js` + `templates/index.html` + `static/styles.css`):
- `requestSkillList()` called on init; skills stored on `this.skills`
- `_renderSkillsGroup` paints the sidebar block — `[PIN]` markers, scope chips, provenance chips, truncated description
- Detail dialog with name, meta strip (`global · agent · used 1× (0 fails) · v1.0.0`), description, full `procedure_md` in a monospace pre, plus Pin/Unpin and Archive actions
- Live update: pin/archive responses trigger a list refresh + close the modal if the viewed skill disappeared

**Iter-card chip deferred**: the `match_skills_for_query` loader exists but is **NOT yet wired into the autonomous mission runtime**, so there's no signal to show. Filed as a v0.6.3+ candidate alongside F1.

10 tests in [tests/test_gui_skill_endpoints.py](../tests/test_gui_skill_endpoints.py).

## a4: archive list + restore

`archive_skill()` was a one-way move — once archived, the only way back was manually fishing files out of `~/.resonant/skills/_archive/`. v0.6.2a4 adds the inverse + a list view.

`orchestration/skills.py`:
- `list_archived_skills(*, scope=None, project_path=None) → list[dict]` walks `_skills_root()/_archive/<scope>/<ts>__<id>/` and returns one row per archive with the loaded `Skill`, `archived_at` ts, `archive_dir` Path, `reason` from sidecar. Sorted most-recent first. Skips malformed entries silently.
- `restore_skill(skill_id, *, project_path=None, force=False) → Path` renames the archive dir back to its original `skill_dir()` location and drops `_archive_reason.txt`. Refuses on live-skill conflict; `force=True` removes the live one first (destructive).

CLI (`resonant-skill`):
- `list --archived` swaps the listing surface to archives. Same `--scope` / `--project-path` / `--json` flags.
- `restore <id> [--force]` brings back the most-recent archive. Exit codes: 0 success, 1 no archive found, 2 conflict (suggests `--force`).

22 tests in [tests/test_skill_archive_restore.py](../tests/test_skill_archive_restore.py) cover idempotency, malformed dirs, multi-archive most-recent-wins semantics, force-overwrite, all CLI exit-code paths.

## a5: field-observation ingest

The field-run finding F1 (trivial-mission-bypass) means the autonomous extractor will miss most "easy win" patterns. Hand-authored field-observation docs should compound into the skill library directly — no model call, no extraction.

New module — `orchestration/field_observation_ingest.py`:
- `_parse_field_observation_md(text)` extracts H1 → name, first non-preamble paragraph → description, full body → `procedure_md` (preserved verbatim).
- `ingest_field_observation_file(path, *, force=False, dry_run=False)`:
  - `created_by="user"` — provenance gate, curator-exempt
  - `pinned=True` — durability gate, auto-deprecation-exempt
  - `scope="global"` — field obs almost always cross-project
  - Idempotent: skips when same id exists, `--force` overwrites
- `ingest_field_observation_dir(path)` walks `*.md`, skips planning docs (`NEXT-RUN`, `TODO`, `DRAFT` heuristics on stem)

CLI: `resonant-skill ingest-field-obs <path-or-dir> [--force] [--dry-run]`

**Live demonstration:**
```
$ resonant-skill ingest-field-obs docs/field-observations/
Ingested 2 file(s) (0 skipped):
  + 2026-05-03-resonant-linux-bridge        Field-observation log — `resonant-linux-bridge`
  + 2026-05-06-v061-self-improvement-loop   Field-observation log — v0.6.1 self-improvement loop

$ resonant-skill list --created-by user
Found 2 skill(s):
[PIN] [user   ] 2026-05-03-resonant-linux-bridge         (global)   First ambitious-greenfield...
[PIN] [user   ] 2026-05-06-v061-self-improvement-loop    (global)   First field run of the v0.6.0+...
```

Both surface in the GUI Skills sidebar at the top of the list. Curator leaves them alone (provenance gate). They won't auto-deprecate (pin gate). Once `match_skills_for_query` is wired into the autonomous mission runtime (v0.6.3+ candidate), they'll match against future missions and feed back into the iter system prompt.

25 tests in [tests/test_field_observation_ingest.py](../tests/test_field_observation_ingest.py).

## What this delivers

After v0.6.1, the loop existed and the production hooks were wired, but the field run found:
1. **The hooks don't fire on trivial missions** (most successful runs miss capture)
2. **Skill names were unreadable** (mid-word truncation)
3. **No GUI surface** for inspecting skills
4. **No way to recover an archived skill** without manual filesystem ops
5. **No way to seed the library from human-authored notes**

After v0.6.2:
1. (deferred to v0.6.3+ — touches grill flow + autonomous_loop)
2. Skill names are short, prefix-stripped, word-boundary truncated
3. Skills sidebar + detail modal in the GUI; pin/archive controls
4. `resonant-skill list --archived` + `restore` close the lifecycle
5. Field-observation docs ingest into user-provenance skills that survive the curator

The user can now write a field-observations doc, run `resonant-skill ingest-field-obs docs/field-observations/`, and that knowledge becomes durable, queryable, surface-able context for future agent runs.
